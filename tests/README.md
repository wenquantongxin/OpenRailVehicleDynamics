测试由 CTest 注册。`BUILD_TESTING=OFF` 时整个测试树不进入构建。

## 判定方式

测试以**退出码**判定，失败时在现场打印足以定位的诊断。

数值测试依据解析解、代数恒等式或独立参考判定。

## 观测语义

判定方按物理量纲区分角度、单位四元数分量、平移、力和力矩，并为近零量使用各自单位的
绝对限。混合自由度按分量保留 N 与 N·m 的区分，不把两者折叠成一种量。

跨实现比较物理观测时，旋转不逐元素比较：九个元素差不合成有意义的姿态误差。矩阵元素
只作传输，由判定方把完整旋转作为 SO(3) 元素检查和比较。位姿组合的代数单测是另一类
契约：它直接逐元素验证矩阵乘法定义，并使用表示精度量级的界限。

## 跨进程比较

参考发射器只产出观测名称与原始数值；物理量类别、必需观测集合与容差判决由判定方独占。

Drake 是迁移期的比较参照，不是本项目交付物的依赖，因此
`ORVD_BUILD_DRAKE_REFERENCE_TESTS` 默认关闭，开启还需要宿主支持 POSIX 进程原语。在按
[平台手册](../docs/build_and_install/README.md)准备好同一工具链的依赖后，可用 `drake-reference`
预设启用；ORVD 依赖与 Drake 的位置均由 `CMAKE_PREFIX_PATH` 提供，仓库不写入机器路径：

```bash
cmake --preset drake-reference \
  -DCMAKE_CXX_COMPILER=/absolute/path/to/cxx \
  "-DCMAKE_PREFIX_PATH=/absolute/path/to/orvd-dependencies;/absolute/path/to/drake"
cmake --build --preset drake-reference
ctest --preset drake-reference --output-on-failure
```

管道测试用两个独立 Drake 进程检查传输、解析与判定，并确认能识别注入的扰动。
ORVD 与 Drake 的比较覆盖位置、空间运动学、微分运动学、质量矩阵、逆动力学/力元与外力/前向动力学；
参考端和候选端使用不同的可执行文件。

空间速度的长期解析测试不从另一条被测查询制造期望值，而是直接使用刚体关系、点移公式和坐标
变换计算。跨进程比较另行覆盖所有场景刚体的角速度与刚体原点平移速度、具名的三坐标系相对
速度以及速度状态回读。内部缓存测试用提交重算次数区分「被标为过期」与「查询时真的重算」。

微分运动学的本地解析测试逐列用公共位姿中心差分核对刚体固定点 Jacobian，并以
`A(vdot)-A(0)=J·vdot` 核对显式加速度。跨进程端使用独立于上下文速度、分量两两不同的稠密
速度探针比较正映射与每个刚体质心处的 `J·probe`，并用不是由正映射生成的独立 qdot 比较逆
映射；完整 Jacobian 的列序与符号由本地逐列有限差分验证。

质量矩阵的公共解析测试不调用第二条质量矩阵实现制造期望值，而是从每个刚体的公共位姿、刚体
原点空间速度、偏心质心和中心惯量组装动能，再用基向量与两两和的极化恒等式恢复完整算子。内部
测试另将复合刚体算法逐列与预分配逆动力学交叉，并让公共刚体顺序不同于森林 Mobod 顺序。跨进程
要求集逐列覆盖全部广义力响应，按每个输出行分别保留 N 与 N·m 的量纲。

持续在线漂移门只运行一个高耦合场景：旋转且平移的安装座、反向转动分支、串联关节和显式自由体共同出现，并分别施加动态与近零激励。单转动、单移动和混合焊接模型的解析/性质资格保留在快速的本地测试中，不在跨进程套件重复构造一份慢速矩阵；证据分工见 [ADR-0004](../docs/adr/0004-focused-dynamics-qualification.md)。在线要求链在质量矩阵之后严格追加速度偏置、重力、阻尼、所需广义力、前向广义加速度和完整状态导数；任一必需观测缺失即失败。

## 参考缓存语义

Drake 缓存测试检查重复求值不重算、整段可变 `q/v` 访问使位置与速度缓存共同过期、
过期条目按需重算及 Context 隔离。序号按「不变」或「严格递增」判定。

## 位姿组合契约

`math/verify_double_pose_composition_contract` 链接**真实符号**
`drake::math::internal::Compose*`，逐一检查四条定义式，并覆盖声明允许的四种输出重叠形态：
输出独立、输出别名第一个输入、输出别名第二个输入、三个实参同为一个对象。

期望值一律先用裸 Eigen 按定义算出，且在调用之前算出——输出别名输入的调用会覆盖掉本该
读取期望值的那份数据。

代数测试的容差按表示精度的小倍数和参与量级缩放；跨实现物理量比较使用对应的物理容差。

## 连续状态推进桥

测试使用两个不同运行期维数的模型核对 `[q; v]` 双向映射，逐项互异的绝对容差原样保留。RHS 持有专用试算上下文，与已接受上下文隔离；合法试算与静态计划一致，非法状态不改接受态或调用方导数输出；异系计划在取得试算状态前即拒绝。桥使用无调用期外力配置。

CVODE 后端测试以自由落体与线性振子对照解析解，一维非自治方程检查回调时间，最近成功内步检查密集输出区间；RHS 抛出后验证原异常类型、公开端点不变、旧密集输出失效、继续推进被封锁，并经显式重初始化恢复。

系统推进测试以单自由度阻尼解析解参数化验证系统桥、CVODE BDF2、Radau5 与同一套接受提交；外部重写 q/v 和关节阻尼后，显式同步使所选后端与试算上下文共同进入下一段且不影响接受上下文。质量与惯量为零的转动支路触发 ABA RHS 失败，接受时间和状态不发布、再次推进被封锁、重初始化后可重新进入 RHS。非法完整状态验证“时间 + `[q;v]`”拒绝原子性。

`[q;v;z]` 测试以车辆力元计划验证具名标称力与串联力状态。力元名称只在
设置阶段解析为系统绑定的强类型索引；右端热路径仍用冻结序号。解析纵切同时核对标称力产生的
分段常加速度与串联元的指数衰减，确认关节阻尼和标称力都由统一入口同步到所选后端的试算上下文；
同一系统事务合同分别覆盖 CVODE BDF2 与 Radau5。

## 积分器资格接缝

Radau5 核心测试除刚性、稠密输出和异常分类外，还直接复用生产 Newton 判定，锁定默认 `NIT=7`
时第 6 次预测的 `dyth<1` 接受与 `dyth==1` 拒绝边界；四维串行 Jacobian 基线另锁定一列一任务、
中间列 recoverable 只缩放并重试该列、fatal 不继续求后续列、RHS 计数分区和端点原子性。正常调用测试覆盖五种方法的显式配置、场景默认值、三个 CLI 的位置参数与选项、
完整状态输出和原子发布。两种机械方法在 GZ18 被动、IRW 被动与受控分支各保留一个短窗冒烟；
公开入口的自由刚体、Ball-RPY 和运动 Maxwell 解析用例保留二阶收敛断言。
独立工具链测试证明干净 Release 配置可通过，并让 `-ffast-math`、`-Ofast`、有限数学假设及
已知等价选项失败；目录级 `-ffp-model=fast`、响应文件中的危险选项和不透明响应文件也会在最终编译
命令处被拒绝，可读的安全相对响应文件则通过。测试还锁定不执行编译启动器的生成器和既存启动器链
必须在配置期响亮失败。该 v1 合同是浮点安全类别而非跨构建逐位身份：编译器默认 contraction、
`-ffp-contract=fast/off` 与融合乘加均允许；两个显式 contraction 选项都必须通过配置审计和最终编译
启动器的真实构建正例。跨编译器／目标构建使用各测试明确的数值容差；同一二进制在不同固定槽 worker 数
下仍必须逐位一致。

独立正确性回归另覆盖每次正长度调用的一次性 stop 吸附及拒步后不重复吸附、持续阶段／误差修正
recoverable 的原异常因果、recoverable 后独立真奇异的优先级、非有限 shift／矩阵／分解分类、正负
大状态的有符号可表示 Jacobian 扰动，以及缩放平方和范数；Newton 修正与误差 WRMS 由两个定向
大尺度场景分别证明不会因先平方而假溢出。适配器测试验证自定义 recoverable 类型、
输出 sentinel、端点、稠密区间、统计、失败封锁和成功重初始化；系统事务测试另要求 accepted
投影历史更新后 Radau5 重建线性化。局部线路投影测试覆盖尺度化残差、严格正二阶条件、至多两次
Newton 校正、定义边界延长和非法输入。
实／复近奇异资格通过源码树专用接缝直接复用生产矩阵形成、分解和求解，以三个逐级缩小谱隙检查
相对后向残差、解析前向误差界和仓外官方 DECSOL oracle；测试不向产品加入条件数阈值。

真实 GZ18 与 IRW 被动/100 Hz 控制短窗把现有全串行运行作为 correctness oracle，再要求
4/8/12/16/32-worker 的完整
`continuous_states.tsv`、物理观测、接触斑、终态及数值统计保持一致。完整状态表按整数纳秒时钟无损
保存 `[q;v;z]`；几何测试按旋转误差核对姿态，不直接相减 raw quaternion／Euler 坐标。

## 安装消费者

安装测试先把当前构建安装到临时前缀，再整体迁移该前缀；随后从独立源码目录仅通过
`find_package(OpenRailVehicleDynamics CONFIG REQUIRED)` 构建八个正常消费者：

| 消费者 | 实际运行内容 |
|---|---|
| `orvd_installation_smoke` | 阻尼转子分别用 CVODE BDF2／BDF5、Radau5、Newmark、Zhai 推进并对照解析解；线路、Ball-RPY 映射及数值失败合同 |
| `configuration_installation_smoke` | 仅链接配置目标，加载已安装的线路、车型、启动状态及关联资产 |
| `track_geometry_installation_smoke` | 仅链接线路目标并执行公共几何计算 |
| `track_irregularity_installation_smoke` | 仅链接不平顺目标并执行空间实现生成 |
| `wheel_rail_contact_installation_smoke` | 仅链接轮轨接触目标并执行公共接触入口 |
| `forces_installation_smoke` | 仅链接力元目标并构造、求值公共力元 |
| `scene_stream_installation_smoke` | 仅链接可移植状态流库，编码、分包、解析报头并解码状态正文 |
| `scene_record_installation_smoke` | 从单刚体模型采样，写入临时场景记录，再读取并核对刚体名称和位置 |

每个消费者必须实际执行且退出码为零；日志逐项记录运行和通过结果。安装元数据不得含原安装前缀、
源码路径或 `/opt`。八个程序统一用现有 CMake 平台运行期依赖检查器检查动态闭包，普通未解析
依赖和共享 Drake 均明确失败。另一个已实际装载 Drake marker 共享库的程序是阳性对照，必须
返回非零退出码，且诊断中明确指出共享 Drake 依赖。测试夹具显式复用当前构建实际采用的
Eigen、fmt 与 SUNDIALS 配置目录，
因此同样适用于依赖位于自定义离线目录的开发环境；安装元数据另行钉住 fmt 查找不得受 `PATH`
上其他工具链污染。
