# ADR-0002：单一权威 Context，树与子系统均为零复制视图

- 状态：**Accepted**
- 决策日期：2026-07
- 相关：ADR-0001

## 背景

Drake 的 `MultibodyTreeSystem` 本身是一个 `LeafSystem`，且树持有指回该 system 的反向
指针并经它求值缓存。若保留这一身份，再在外层叠一套自写运行时，就会出现**两套 Context
各存一份 q/v**。一旦两份状态或两套缓存不同步，数值差异会被误判成多体核的问题，而不是
被识别为同步问题。

## 决策

**全项目只有一个权威运行时上下文。** 第一方公共类型必须按实际职责命名，不直接占用含义
过宽的裸 `Context` 名称。

- 后续系统组装层的根上下文唯一持有时间、连续状态、实际参数与输入版本；G21 的多体求值
  上下文只持有 tree 实际消费的 q、v、类型化物理参数、对应版本与缓存工作区，不为时间、
  端口、离散状态或事件预留字段。
- 最终化模型不可变并可由多个多体求值上下文共享；每个上下文独占可变状态、版本与缓存。
  多体树与其余子系统都是**零复制求值者**，由 tree 接收上下文，不由上下文反向定位 tree。
- 首版状态修改先完整验证，再一次写入；失败保持活状态不变。公共 API 不返回可在版本推进后
  继续写入的长生命周期可变视图，也不提供先修改活数据、随后提交的编辑器。
- 把 vendored 树降为**纯求值内核**，消解其 `LeafSystem` 身份与反向指针，其缓存声明改为
  绑定到原生缓存目录。
- **必须实现正确的缓存失效与按需重算语义**：Drake 的树通过 `CacheEntry::Eval` 求值，而
  `Eval` 内部检查新鲜度并在失效时重算。因此原生实现欠的不只是存储，还有"什么时候该重算"
  这一判定本身；但不复制 Drake 已知保守的 q/v 共同失效粒度。

缓存条目、值类型、先决条件与**实现机制**由 G20 从 G16 后的 landed 源码、G17 的编译
前沿和固定 Drake 来源中的 `MultibodyTreeSystem` 职责现场裁决，不在此预先写死。首版不
照搬 Drake 的通用抽象参数、离散状态、事件状态或运行时类型擦除；确有消费者的非数值状态
使用具名、定类型存储。每个缓存直接观察经实测需要的版本源，不预造通用依赖图。运行时
基础层只提供状态、版本和不依赖具体值类型的类型化缓存槽；刚性树接入层单向依赖它并组成
具体缓存工作区，公共门面再单向依赖接入层。

## 后果

- 消除双 Context 风险；求值次数与顺序可审计。
- 已预热上下文修改后求值与同输入冷上下文对照，用于发现少失效；无关修改下的重算次数用于
  发现多失效，不把 Drake 当前 q/v 共同失效当成正确答案。
- Context 与缓存的自写层是这一阶段的主要工作量与主要风险。
- 约束下沉：拒步时向量外的状态也必须回滚——普通成员变量不会自己回滚。
