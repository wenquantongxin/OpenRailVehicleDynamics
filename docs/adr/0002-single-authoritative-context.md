# ADR-0002：单一权威 Context，树与子系统均为零复制视图

- 状态：**Accepted**（REV2 新增，源自第二轮审查 B2）
- 日期：2026-07
- 相关：ADR-0001

## 背景

vendored 的 `MultibodyTreeSystem` **本身就是** `systems::LeafSystem`，且树持有 `tree_system_` 反向指针、
经它求值缓存（multibody_tree.h:2211-2215）。若保留这一身份，再在外层叠一套自写 mini-systems 的 Context，
就会出现**两套 Context 各存一份 q/v**——这是初稿未想透、并在第一轮审查中被点名的最致命暗礁之一：
一旦两份状态或两套缓存不同步，数值差异会被误判成多体核问题，且求值次数（接触温启动可观测）会漂移。

## 决策

**全项目只有一个权威 Context。**
- 根上下文唯一持有：时间、连续/离散/抽象状态、参数、输入版本号、事件状态。
- 子系统上下文与多体树都是**零复制视图**：树只接收 `q/v/参数/外力` 视图 + 独立求值缓冲。
- 把 vendored 树**降为纯求值内核**，消解其 `LeafSystem` 身份与 `tree_system_` 反向指针；
  15 处 `DeclareCacheEntry` 由自写 Context/cache 顶替（约 4–8 kLOC 生产代码）。
- 缓存语义保留但简化：状态/参数/输入/时间版本号 + 按需记忆化 + 试算/接受双态；
  12 项状态缓存每 RHS 失效，3 项纯参数缓存（reflected inertia / joint damping / frame body poses）参数变更才重算。

失败回退（仅在纯求值内核化受阻时）：临时多 vendor 一层 Drake 窄框架兼容层，代价 +5–10 pw 与更大移植面。

## 后果

- 正面：消除双 Context 风险；求值次数/顺序可审计，利于有序轨迹 parity。
- 负面：Context/cache 自写层是 M2 的主要工作量与主要风险；"每步全算"不可替代版本化缓存与事务语义。
- 约束下沉：拒步时向量外状态（温启动提示、PID 积分/抗饱和累加器）必须显式事务性回滚。

## 出处

设计基线 §2.4、§4.3、§10.1（A2 反向指针）、§10.2（新增硬约束 2、3）。
