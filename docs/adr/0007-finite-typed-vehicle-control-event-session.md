# ADR-0007：车辆周期控制采用有限类型化事件会话

- 状态：**Accepted**
- 决策日期：2026-08-11
- 相关：ADR-0002、ADR-0003、ADR-0004

## 背景

G73–G75 已分别建立 IRW 构架—独立车轮转矩作用对、转矩指令调理和 100 Hz 全状态控制纯递推。
G76 需要把三者接入完整车辆，同时保持单一权威运行时上下文、CVODE 接受态事务和 P179 的启动
双更新时相。当前只有一个已资格的固定周期消费者，不存在通用字符串事件总线、任意周期集合或
车型间共享动态事件插件的产品需求。

## 决策

IRW 100 Hz 控制由配置层的有限类型化事件会话驱动。会话在装配期从与接触和主动转矩共同使用的
封闭车型表解析四个轴桥体与八个车轮关节；事件期只读接受上下文已有的四个投影站位、体位姿和
关节速率，不重新投影、不调用接触核、不做名称查找。

事件会话拥有控制器状态、调理器记忆、整数事件序号和同步阶段；八路零阶保持转矩仍由
`SystemRuntimeContext` 唯一拥有。控制器和调理器先产生完整候选值，全部成功后才提交八路保持转矩、
两组后态和下一序号。控制器与调理器周期必须逐位相等且为 `10 ms`，事件时刻由整数序号乘共同周期
生成，禁止累计浮点加法。

启动时在同一 H3 接受态先执行一次只推进记忆的完整周期初始化，再执行 U0 并提交其保持转矩，随后
才构造连续状态推进器。每个非终点周期边界在事件提交后显式调用
`SynchronizeAfterAcceptedContextChange()`；终点事件照常提交两组后态和保持转矩以形成完整审计，
但不为不存在的未来正时长区间重初始化后端。

事件计算失败不提交控制记忆或保持转矩；事件已提交而后端同步失败时不回滚、不重复递推，只封锁
后续推进并重试同步。该协议保持在车型配置层，不下沉为模型中立的通用事件框架。

## 后果

- P179 的当前接受态观测、启动双更新、10 ms 零阶保持和事件后 CVODE 同步具有一个明确消费者；
  SIMAT 上一通信拍观察龄继续只作为模型差异记录，不形成运行时人格开关。
- 控制器算法和调理器仍是状态显式的纯递推，可独立测试和复用；车辆层只承担具名观察排列、事件
  所有权和提交时相。
- 后续 MPC、强化学习、模仿学习或其他采样控制器在出现真实共同需求前各自使用类型化会话，不从
  本次单一消费者预先抽象通用事件总线。
- G76 的 `0.5 s` 资格运行按事件序号保存内部控制审计；该工件不是公开输出格式，也不把积分器差异
  造成的后续机械轨迹分岔误写成控制算法逐位金标。
