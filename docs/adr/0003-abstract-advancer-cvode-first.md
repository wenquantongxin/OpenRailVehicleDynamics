# ADR-0003：抽象推进器接口 + 首版只实现 CVODE 后端

- 状态：**Accepted**（范围开关 S1，REV2 扩充语义集）
- 日期：2026-07
- 相关：ADR-0002

## 背景

GZ18 路径同时使用两条积分驱动：外置 SUNDIALS CVODE（`cvode_driver.cc`，RHS 唯一 Drake 触点在 :51）
与 Drake `Simulator::AdvanceTo` + `ResetIntegratorFromFlags`（main.cc:518 等）。Drake 积分器族实测 5,615 LOC。

第二轮审查证实：仓库 CVODE 线是"先更新后发布"（publish 见 x⁺），Drake AdvanceTo 是挂起更新、
先对 x⁻ 发布——**两族语义不等价**。本项目复现目标是 CVODE 线的当前行为。

## 决策

整车推进循环定义**抽象推进器接口**，**首版只实现 CVODE 后端**；Drake 积分器族仅预留目录不实现。

接口须捕获的最小充分语义（B4 七项，取代初稿五项）：
1. 初始化次序（非受限更新 → 离散更新 → 发布）与失败/终止状态传播；
2. 同刻事件稳定排序、x⁻/x⁺ 可见性、零时间级联保护；
3. 区分"下一发布时刻"与"下一更新时刻"，并夹持积分边界；
4. RHS 试算纯净、接受步提交、拒绝步回滚；密集输出采样不得提交温启动；
5. 状态/参数/输入改变后显式通知 CVODE 是否需要重初始化；
6. 事件失败、提前终止、能力查询；
7. 对 v1 不支持的 witness / 逐步事件 / 监视器**显式报"不支持"**，不静默忽略。

事件调度归整车运行时；CVODE 后端只负责接受步推进、插值、重初始化——避免退化成只包一层虚函数的空抽象。

## 后果

- 正面：省去 5,615 LOC Drake 积分器移植；保留日后补第二积分器族（drake_family/）的通道。
- 负面：只有一个后端的抽象接口有腐化成空壳的风险——以 B4 七项语义 + 接口文档显式记录两族不等价来对冲。
- 背景（范围外）：`SIMPACK-Drake对齐列表.md:85` 记有宽松 BDF2 约 26° 相位色散、`cvode_max_order` 默认 2；
  该关切属 SIMPACK 对齐线，不影响本项目"复现当前 CVODE 行为"的目标。

## 出处

设计基线 §3.4、§5.1（S1）、§10.1（B4）、§10.2（新增硬约束 4）。
