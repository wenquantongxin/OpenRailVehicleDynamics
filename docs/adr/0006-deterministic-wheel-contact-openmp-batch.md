# ADR-0006：八接口轮轨接触采用确定性 OpenMP 批求值

- 状态：**Accepted**
- 决策日期：2026-08-09
- 相关：ADR-0002、ADR-0003、ADR-0004

## 背景

G52–G58 已先以串行路径闭合 GZ18 单轮接触数学、八接口车辆 RHS、接受步事务和长窗资格运行器。
近期 WRL P056/P057 正式运行又表明，轮轨接触占完整 RHS 的绝大部分，八个轮轨接口是天然独立且
已有真实八线程消费者的承重热点。ORVD 需要在 G60/G61 的 `10 s/20 s` 长窗前准入并行，但不得
改变轮序、物理人格、上下文所有权或失败事务。

项目负责人明确，同一进程中不存在不同车辆分别选择线程数的需求。因此不建设车型级线程字段、
通用线程策略公共 API、自建线程池或环境变量到物理配置的映射。

## 决策

每次轮轨力求值分为三段：

1. 四个载体的多体位姿、速度、线路投影和轨道运动学保持串行。
2. 八个冻结轮轨接口使用 OpenMP `schedule(static)` 并行计算。每个接口在所属
   `SystemRuntimeContext` 中永久独占一个构造期预热的接触工作区、一个固定结果槽和一个异常槽；
   不按 OpenMP 线程号借工作区，也不在接口间做浮点归约。
3. 隐式屏障后先按冻结 ordinal 检查异常，重抛最低 ordinal 的异常；只有全部成功时才按同一轮序
   发布扳手和观察。并行区内不得让 C++ 异常越过 OpenMP 结构块。

标准 OpenMP 进程执行环境控制可用线程数；产品只读取运行时查询结果，不调用
`omp_set_num_threads()`，最大请求数为
`min(8, interface_count, omp_get_max_threads())`。`OMP_THREAD_LIMIT` 等进一步约束仍由 OpenMP
运行时执行，不要求产品调用 OpenMP 3.0 才加入的查询接口；请求数为一时执行真实串行循环。
OpenMP 是 `orvd_forces` 的私有实现依赖，但静态安装包必须通过
`find_dependency(OpenMP COMPONENTS CXX)` 恢复其链接闭包。

## 后果

- 同一状态在 1／2／4／8 线程下没有跨轮运算次序差异，八个扳手、八组观察和完整 RHS 应逐位相同。
- 每个运行时上下文从一个接触工作区增为八个；GZ18 八份接触工作区总计约 `5.1 MiB`，较原串行
  所有权增加约 `4.4 MiB`。accepted、candidate 与离线观察三份上下文的接触工作区合计约
  `15.2 MiB`。这是确定性所有权成本，不以共享池或线程号缓存换回。
- 标准 OpenMP 环境属于数值执行身份而非物理人格。资格工件记录动态团队开关、运行时最大线程数、
  产品上限和解析后的请求数；硬件、绑核、墙钟和峰值内存仍只进入仓外性能报告，不成为数值金标。
- G59 不改变 CVODE 算法、容差、接受事务、单轮接触公式或接口观察合同；SPGMR、稀疏 Jacobian、
  BLAS／LAPACK、持久线程池和跨车辆调度均保持后续范围。
