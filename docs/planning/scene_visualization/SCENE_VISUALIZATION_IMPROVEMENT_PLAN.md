# 三维场景显示计划

让不同车型、线路和工况共用场景数据、离线回放与实时观察能力。

## 职责

- `scene_observation` 提供拓扑、位姿和物理读数，`scene_record` 保存离线记录。
- `state_stream` 负责消息编码与传输，协议编码和操作系统 socket 分离。
- 查看器负责渲染与交互；车型外观、角色和名称由视觉定义提供。

显示消费已发布样本，数值推进与控制时钟由运行程序管理。
文件与实时输入共用场景定义和样本语义，静态资源、离线历史与实时缓冲分别管理。

## 推进路线

| 批次 | 内容 | 状态 |
|---|---|---|
| 一 | 离线长线路分段绘制、局部坐标、静态定义与样本访问解耦 | 已实现 |
| 二 | 共用场景描述、独立静态资源读取、通用线路导出、可移植编码与 OSTS 规格 | 下一步 |
| 三 | Node 接收服务、WebSocket 样本源、有界缓冲、重连、运行切换与记录回放发送器 | 后续 |
| 四 | 外部生产者按公共合同接入，验证连续长线路实时观察 | 后续 |

## 车型与图层

- 补齐 GZ18 真实记录导出与拓扑测试，更新 IRW 演示记录；载体标量显式使用载体定义的 `body_name`。
- 逐斑接触点与力箭头使用真实接触观测；不平顺图层使用运行中的空间场采样。
- 美术细化沿用参数化零件、共用材质与相机，布局和名称在车辆视觉定义中维护。
