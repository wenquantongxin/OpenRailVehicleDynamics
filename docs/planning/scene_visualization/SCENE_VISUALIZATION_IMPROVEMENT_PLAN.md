# 三维场景显示综合完善计划

本计划说明 ORVD 三维显示的长期边界、当前进展与下一阶段重点，现状核对日期为 2026-09-28。已完成的接口整理不再作为待执行任务重复排列；具体字段以公共接口和记录说明为准，一次性预分析、夹具与截图留在临时工作目录。

目标是让不同车型、线路和工况共用同一套观察与显示能力。原生计算提供可信的物理结果，公共场景层表达其含义，查看器负责清楚地呈现；增加车型主要补充显示数据，而不是复制前端或另造运动状态。

## 1. 方向与边界

- **观察是公共能力，网页是消费者。** 场景数据与采样归属 `libs/scene_observation`，离线记录归属 `libs/scene_record`；渲染、相机、布局和交互留在 `apps/scene_viewer_web`。公共层不依赖 React、Three.js 或 UDP。
- **显示不决定求解。** 不为了屏幕帧率增加积分停靠点、改变步长或控制时钟，也不改变接受态提交时机。离线回放的刷新率、倍速和定位只影响显示。
- **车型差异由数据表达。** 物理关联来自模型与记录，示意零件、双语名称、显示次序和角色来自车辆库的独立视觉 JSON；不按名字、距离或车型分支猜关系。
- **外观保持轻量。** 使用基本几何与参数化轮截面，不新增或复用 STL 等网格资产；尺寸和外观是示意，不冒充制造几何或真实接触型面。美术参数不进入机械配置。
- **独立消费，不绑传输。** 文件记录、本机实时接入与第三方 UDP 只共享数据含义，不共享必经协议；自包含查看器不依赖 UDP 转 WebSocket，不涉及 RCZ 或第三方 UE 路线。
- **只做实际需要的抽象。** 同一查看器内部共享模块即可，暂无第二个前端消费者时不拆独立 npm 包，不引入插件体系、事件总线或无人消费的接口。
- **保持单一当前契约。** 允许破坏性更新，同时迁移受影响的仓内生产者、消费者与测试；不留兼容别名、旧格式读取器或迁移开关。遵守 NO SHA，不以提交号、摘要或哈希识别配置、绑定安装件或判断兼容性，不增加格式版本分支。

命名、可信输入边界和接口更新继续遵循[第一方工程约束](../../engineering/FIRST_PARTY_ENGINEERING_RULES.md)。本计划不自动启动全部后续工作，也不要求新增 ADR、审查流水线或文献表。

## 3. 长期保持的职责与数据语义

### 3.1 一份物理来源，多种显示消费

```text
ORVD 模型与成功提交／返回的状态
                  │
                  ▼
scene_observation：拓扑、位姿、显示所需物理量及其坐标与单位
          ├── scene_record：完整离线记录
          ├── 应用侧本机实时适配（后续）
          └── state_stream：独立第三方输出

记录／后续实时输入 + 车辆库视觉定义
                  │
                  ▼
查看器：输入解析 → 一次性显示绑定 → 场景、读数、相机、标注
```

公共层不读取视觉 JSON 来判断物理关系；记录层原样携带视觉定义；查看器在装载边界将显式名称解析为槽位与分组，随后各模块共用，不逐帧重新发现拓扑。新增车型优先使用现有共同导出路径与显示模块，只有具体数据需求无法表达时才扩展公共接口。

视觉定义的构架成员列表表达显示归组，不是动力学父子关系。车轮通过记录中的载体关系继承分组；左右轮可以共用同一个轮对刚体，不能因刚体槽位相同而丢掉一个轮位。位置用于尺寸与排版，不决定身份，也不覆盖明定端序。

### 3.2 坐标、角度与缺测不被外观改变

- ORVD 惯性系 `+z` 向下；随线路变化的纵横方向属于当地线路系，不能把固定惯性 `+x` 当作整条曲线的增里程方向。刚体位置、原点线速度与角速度按记录的世界系表达。
- 四元数为体系到世界系的旋转，顺序 `w,x,y,z`；Three.js 的坐标显示变换只在统一根节点做一次。视觉零件的局部坐标相对所属刚体原点，不相对轨顶，也不把 IRW 的体基约定套给 GZ18。
- 站位是平面投影里程，不是三维弧长。线路姿态和轨面基准来自记录；浏览器不重写曲率、超高、竖向剖面或接触轨面的定义。
- 表中 `yaw_radians` 保留记录的体基 X–Z–Y 分解定义；载体俯视示意采用轮轴在当地线路系中的航向，两者不能混称。轮轴投影退化时显示不可用，不填零角度。
- 位姿已含车轮自转，未折返角只用于选择帧间插值分支，不能再叠加一次。GZ18 刚性轮对没有独立回转副展开角，当前沿用姿态插值；采样不足时提示限制，不按车速除半径编造多圈信息。四分之一周的警告阈值与半周的最短路径歧义边界不是一回事。
- 原单位在记录与计算中保留，毫米、毫弧度和千牛只在显示边界转换。未知、占位、未记录与有效零值分别呈现，未知接触不能当作单点或无接触。
- 无视觉定义时仍保留载体归组、左右轮、轮重与接触状态等已有信息；缺少的是车体／构架角色及依赖它们的视角和读数，不是整份记录失效。引用不存在的刚体与刚体缺少某个标量是不同问题。

帧布局、整数身份范围和缺测状态集中见[场景记录说明](../../../libs/scene_record/README.md)，不在计划里维护第二套格式规格。

### 3.3 命名和抽象服务于跨车型复用

跨模块名字保留对象、必要坐标系与单位，并与记录词汇对应；不为长度本身改名。帧表行号用 `frameIndex`，记录样本身份用 `sampleIndex`，参考系用 `trackFrame`／`bodyFrame`，列偏移用 `ColumnOffset`，里程值与循环下标分别用 `stationMeters`、`stationIndex`。

共用代码使用 carrier 等真实领域词汇，界面“轴桥／轮对”等具体名称由数据提供；`AxleboxCarrier` 与轮轨接触载体不能混称。紧邻公式的数学短变量可以保留，不给通用相机、播放或线路算法加车型前缀。

记录读取、插值、播放、基础几何、材质、轮截面、线路、相机与卡片已可复用。后续素材扩充不应重新引入名称猜测、尺寸硬编码或专属车型页面。

## 4. 下一阶段重点

### 4.1 优先完成真实数据接入

下一项功能交付是让 GZ18 沿已有公共链路导出并回放真实记录，同时补齐 IRW 的当前格式记录；不再重复前两批整理，也不新建 GZ18 导出器。

剩余关键事项有明确边界：

- 共同运行器的载体标量前缀和载体刚体查找均显式取 `carrier_definition(i).body_name`，接口标量仍以接口名为前缀。当前两车的 carrier 名恰好等于刚体名，因此这是解除隐含假设，不是修正两车既有仿真结果。
- GZ18 入口、运行配置与包装入口接通可选场景输出，复用共同样本处理与写入逻辑，并保留既有积分器配置透传。
- 正式纳入 GZ18 拓扑测试，核对安装消费者；用短直线与短曲线记录确认同体左右轮、标量、镜头和跟随，不扩展为长窗性能比较。
- 旧演示记录通过完整导出路径重新生成，不手工补字段后当作真实闭环证据，也不增加兼容读取。

GZ18 当前资格配方要求显式指定不平顺资产，短记录也遵循该规则，不增加 `none` 特例或改写冻结场。当前线路表仍是设计线形，不能因此宣称已经显示实际不平顺钢轨。

当前 `tools/dynamics_qualification`、相关资格测试和 `tests/CMakeLists.txt` 属于并行任务改动范围。上述应用端工作等待该任务完成交接后再落位；这是文件与执行资源的协调，不是按某个提交号判断能力。公共字段与前端已完成，不需要为等待交接保留两套契约。

### 4.2 美术可以沿现有骨架继续

IRW 与 GZ18 已有明确绑定和可检查的示意体，美术细化不必等待全部真实记录导出，但只能将程序化夹具用于外观与交互核对，不把它们包装成仿真结果。

继续采用暖浅背景、半透明外壳、橙色运动件、双侧信息卡和引线标注。车型差异主要落在各自视觉 JSON 的零件布局、示意尺寸与双语名称；材质、几何生成、相机拟合、标签避让和卡片保持共用。

附着点可以作为零件布局依据，不能从质量、惯量或重合的力元端点推导不存在的实体尺寸。GZ18 局部坐标以所属刚体原点为基准，后构架沿用机械定义中的自身坐标，不凭外观对称性擅自镜像。默认按原比例显示；以后若增加放大或变形，必须明示倍率与图层。

本阶段完成的标志是两车在同一查看器中结构可辨、名称可读、常用视角完整入镜，且美术改动不改变记录语义或掩盖缺测。程序化运动的校正只修夹具，不应反向修改动力学模型。

## 5. 后续研究量展示：先有来源，再有图层

### 5.1 接触点与力箭头

轮级力与斑数不足以恢复接触点，新增叠加必须消费 ORVD 的真实接触观测。公共场景层使用同次求值的 carrier 站位，将接触点与力从 carrier Track-T 转到惯性系，分别处理点的平移与向量的旋转；侧别轨型参考站位不能代替 carrier 站位。只有现有公开数据确实不足时才补窄字段。

接触求值使用独立观察上下文、自有工作区和该样本所需的保持量与投影历史，不污染积分器状态或缓存。逐斑数据保留时间身份、接口与有效状态；一次求值的斑序号不是跨时间身份，不跨斑生灭连线或插值，也不凭力值虚构真实接触椭圆。

导出频率由观测需求和成本决定，不受屏幕刷新率支配。当前场景记录不含完整连续状态与投影历史，不能承诺离线仅凭位姿补算接触。

### 5.2 实际不平顺场

从本次运行实际使用的空间场按里程采样，不在浏览器按 PSD 名称或 seed 重新生成。保留设计线形与实际位移图层的区别，明确参考系、通道、单位、placement 和有效范围。

位移显示不等于接触求解器的完整轨面放置。放大图层不能与未放大的车轮位置混用来判断接触误差；现有 AAR／ERRI 生成、冻结资产与车辆工况不因显示而改变。

## 6. 本机实时：观察数值推进，不驱动数值推进

实时接入属于后续应用能力，不是现有离线记录的隐藏模式。区分仿真时间、样本时间与浏览器墙钟刷新时间；相机和发送频率不反向决定求解与采样时刻。

当前稠密采样在公开推进调用成功后返回样本，资格场景记录再处理这些样本，不是逐内部步在线发布。对于本来就有控制或应用事件边界的运行，可在成功返回后将完整场景帧交给有界的最新帧槽，由应用侧独立发送；不共享可变 Context，不让慢客户端阻塞仿真或积累无界队列。离线和实时输入最终使用同一套场景与读数模块，接入时才增加所需适配。

一次调用覆盖整窗的运行仍结束后回放。确需中途观察时，另行明确输出时机与失败事务，不能为 30／60 Hz 显示拆分推进，也不把未关闭记录当作当前可读的实时通道。

“不干扰积分”指不改变推进与状态语义，不代表采样、复制和传输没有墙钟成本。后续验证应区分数值结果／积分工作量与观察开销，并确认浏览器停顿或断开不会造成反压。前端物理参数调节、任意外力拖拽和远程控制不在本计划内。

## 7. 验证与协作方式

保持三类证据各有用途：小型程序化夹具检查显示和接口，真实装配测试检查拓扑来源，短仿真记录检查完整导出与回放。截图不能替代坐标核对，夹具不能替代动力学结果；临时手工编译通过也不等于测试已正式注册。

- 沿用现有场景 C++ 测试和前端测试、类型检查、打包，不为每项功能再建流程。公共头或安装边界变化时做相关消费者核对，CSS 和视觉资产修改不触发全量安装。
- 保持 `ORVD_BUILD_STATE_STREAM=OFF` 时公共采样、记录与回放可用；只有涉及第三方组件依赖时才验证它，不顺带改协议。
- 检查两种轮体关系、不同体基、缺少视觉定义或标量、窗口变化与常用视角；测试围绕真实语义，不用固定截图、文件数量或构建身份作兼容门槛。
- 只构建和运行直接相关小目标，资源使用遵守当次约定；不替换正在使用的安装，不启动强化学习或无关长仿真，不碰尚未交接的并行改动。
- 临时预分析、生成器、记录与截图留在 `tmp/scene_visualization` 等忽略目录，不成为产品构建依赖。需要长期维护的测试进入仓内目标，资产更新同步其简短说明。
- 每次收口核对差异与实际完成边界；经用户授权后按历史中英 Git 格式提交，只纳入本次相关文件。
