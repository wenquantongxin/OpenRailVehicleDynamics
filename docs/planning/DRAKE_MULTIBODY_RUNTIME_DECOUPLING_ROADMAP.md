# Drake 多体运行时脱耦路书

本文件是 ORVD 当前唯一的实施路书。它把项目拆成 18 个子目标、50 个原子 Goal。
每次 Goal 模式只执行其中一个 Goal；不得在执行过程中重新规划整条路线或顺手扩展范围。

## 当前状态

- 工作分支：`main`
- 当前阶段：实现单一 Context 状态所有权
- 当前 Goal：`G26`
- 产品代码状态：vendored common support、topology 与 double pose math 三个静态库可构建，
  四个位姿组合函数有常驻契约测试；刚性 tree 源码已落位，其编译前沿受阻于三个待替换的
  运行时头；第一方运行时已落地状态布局、类型化参数存储、五个版本源与通用类型化缓存槽，
  八种依赖集合已有合成矩阵验证，惰性求值和刚性树具体缓存目录尚待 G25–G27
- 已验证平台：Ubuntu 24.04 + GCC 13。Clang、MSVC 与 Windows 尚未实测，不提前宣称
  已跨平台；正式资格门仍是 G46
- 仓库外探针：只作一次性研究输入，不直接复制进产品

## 不再讨论的前提

- 采用方案 B：先 vendor Drake 刚性多体树与拓扑，再逐步替换。
- 产品只支持 `double`；运行期不保留自动微分或符号标量。
- 最终产品不链接 `libdrake`。
- Eigen、fmt、SUNDIALS CVODE、Ceres 是允许的外置第三方。
- 保留模型中立的系统组装层；首个推进后端是 CVODE。
- GZ18 在模型中立运行时稳定后接入，不参与底层接口塑形。
- 连续量以工程相对误差 `1e-3` 为主；近零量使用按单位声明的绝对限；旋转使用 SO(3) 角度。
- 不保存数值金标、输出快照、文件哈希或平台结果档案。
- 可信本地生成器产生的探针输入采用宽松解析；只检查实际使用字段能否解析及维数是否正确。
- 不提供旧名称、旧格式、旧接口或错误实现的回退兼容。

## 仓库外原型的处理规则

仓库外已存在可运行的启动器、参考发射器与缓存探针。它们**既不整文件迁入，也不盲目逐字重写**：

1. 先由 Goal 确定主线的长期接口，再逐函数审查仓外实现。
2. 只有脱离旧协议、脱离硬编码场景、脱离探针目录结构的**纯算法片段**可以选择性采用，并按第一方工程规范重构。
3. 现有启动器把场景定义、线协议、比较判定和进程管理混在一个文件里，不得整体复制：G06 吸收场景语义，G07 重建比较职责，G08 吸收缓存事实。
4. 主线测试承接必要知识后，仓库外探针整体删除，不归档、不留压缩包或软链接。

## Goal 模式规则

每个 Goal 必须满足以下格式：

```text
Goal GNN — <明确的功能名称>

前置 Goal：
唯一产物：
允许修改：
明确不做：

完成门：
1. <可执行、可判定>
2. <可执行、可判定>
3. <可选第三项>
```

执行纪律：

1. 一个 Goal 只产生一个逻辑产物；直接测试和必要说明随产物一起完成。
2. 默认在同一工作分支连续推进，一 Goal 一个聚焦提交；不为 50 个 Goal 创建 50 个分支。
3. 每次开始前读取本路书中的 Goal 定义和直接前置产物，不重新审议已定路线。
4. 完成门全部通过才标记完成；失败就在当前 Goal 内修复，不用兼容层绕过。
5. 若发现必须改变已接受架构，停止当前 Goal，先单独形成明确的新决策。
6. 构建产物、日志、临时观测、性能输出、金标和哈希不进入 Git。
7. 探索性测试用完即可删除；保护核心语义的短测试长期保留。

## 子目标 8：实现单一 Context 状态所有权

- [x] **G20 — 定义多体树运行时契约与实际缓存依赖映射**
  - 产物：逐项列明 landed tree 对 systems 类型、状态、参数和缓存入口的实际消费处，

    landed 源码、G17 编译前沿和固定 Drake 来源，不依赖尚不存在的完整 tree 目标。
  - 完成门：表内无未裁决项；确认 tree 不读取时间、精度或输入端口，没有准入派生元素
    覆盖 `DoDeclareDiscreteState`，现存离散机制只是待删除的 framework 脚手架；
    `parameter_conversion.h` 只服务 `BasicVector` 参数打包。ABA 内部仍读取 mobilizer
    锁定状态，但没有已批准的产品功能或场景需要锁定，因此其 API、存储和算法分支随 G26
    整链删除，不建立抽象状态容器。
  - 架构边界：最终化模型不可变并可由多个求值上下文共享；G21–G22 先建立独占 q、v、
    类型化参数和版本的状态实例，G27 再把该实例与具体缓存工作区组合为内部求值上下文。
    调用方向为 tree 接收上下文，依赖方向固定为「运行时状态/版本/通用类型化槽 → 刚性树
    接入层的具体缓存工作区 → 公共门面」，不预造 Diagram、事件、端口或通用依赖图。
  - 实测结论：契约表见
    [`docs/design/MULTIBODY_RUNTIME_CONTRACT.md`](../design/MULTIBODY_RUNTIME_CONTRACT.md)。
    落位树里没有任何具体缓存声明，只有 `MultibodyElement::DeclareCacheEntry` 通用转发器，
    因此声明侧取自固定来源的 `multibody_tree_system.cc`，消费侧取自落位源码，两侧对账。
    契约把三件事分开记——Drake 声明的新鲜度先决条件、计算时实际读取的上游、ORVD 采用的
    语义根依赖——三者不等价，混起来会得出错误的依赖结论。
    保留的状态/参数缓存，其传递闭包都落在 q、v 与语义化参数版本上，因此新鲜度判定可以
    只保存根版本快照，不建 ticket 图或通用依赖图；Drake 对 ABA force cache 与
    Accelerations 的声明保守包含时间、精度和输入端口，ORVD 刚性树内核改为显式接收调用期
    施力并使用工作区，不把外层 system 的声明包络复制进长期缓存。
    参数按实际读取拆成有证据的类别：改一个刚体质量只影响惯量一支及其传递依赖，
    不使位置、速度、跨节点 Jacobian 或空间加速度偏置重算，
    而 Drake 的 `all_parameters_ticket()` 会让全部缓存过期——上游自己在该处留有
    「Create more granular parameter tickets」的 TODO。
    另定：joint damping 缓存删除、阻尼力在 G35 直接计算；system Jacobian 首版直接计算，
    不预分配缓存；重力向量归为最终化后不可变的模型数据，不建缓存版本。

- [x] **G22 — 实现状态版本与实例隔离**
  - 产物：广义位置、广义速度和 G20 证明会影响缓存的参数版本，以及独立的多体状态实例；
    具体求值上下文到 G27 才与 tree 缓存工作区组合。
  - 完成门：一次成功修改只推进对应版本一次，失败的修改保持状态与版本均不变；没有缓存
    消费者的状态不为对称性凭空获得版本源，热路径不复制整块状态。
  - 隔离门：两个状态实例可引用同一不可变最终模型，但不共享状态或版本；修改其中一个
    不会改变另一个。G27 组合缓存后继续保持同样的上下文隔离。
  - 实测结论：版本源恰好五个——广义位置、广义速度、全部固定坐标系位姿、全部刚体惯量、
    全部执行器转子惯量与传动比。三类参数在 G20 契约中的长期缓存消费者集合两两不同
    ({3,4,6,7,8,9,10,11,12,13}、{3,6,7,10,11,13}、{1,11,13}),因此不能合并;
    关节阻尼、转动弹簧与线性衬套无缓存消费者,不获得版本源。参数按类别整体版本化,
    不按元素:相关缓存都是整模型缓存,没有能只对一个 body、frame 或 actuator 失效的消费者。
    `MultibodyStateVersion` 只比相等、只产生后继,不隐式转整数、不做算术、不排序;成功
    提交即推进,不做值比较——少推进会静默给出陈旧答案,多推进只是白算一次且被重算计数
    看得见。每次带版本的写入固定为「校验 → 算后继(耗尽则明确失败) → 写入 → 提交版本」,
    因此计数耗尽不会留下「数据已写、版本未推进」,后续单线程求值也不会在旧数据仍在原处时
    看见新版本；这不是并发同步机制。
    版本计数耗尽分支经公开 setter 理论可达,但常规测试无法实际覆盖:须先完成
    2⁶⁴−1 次成功写入再发起一次；不为这一条直白分支增加生产测试钩子。
  - 判别力：常驻测试覆盖五类成功写、同值重写、失败原子性、三类无版本参数和双实例隔离；
    实施时的错误类别、双推进、提前推进与遗漏推进扰动均会使测试失败，扰动本身不入仓。

## 子目标 9：实现固定类型缓存

- [x] **G23 — 实现通用类型化版本缓存槽**
  - 产物：运行时基础层提供由值类型、版本快照与新鲜度组成的预分配槽机制；它不引用

  - 完成门：热读取不经字符串、`AbstractValue` 或运行时类型擦除；模型最终化后由接入层
    组成的槽布局冻结，不能追加。
  - 边界：具体位置、速度、惯量和 Jacobian 工作区归 G27 刚性树接入层；带调用期外力的
    articulated-body force/forward-acceleration 结果直接计算或使用调用期工作区，逆动力学
    的规定加速度同样只作调用参数；
    其中 Jacobian 工作区指跨节点 `H_PB_W`，不把 G33 首版直接计算的
    `BlockSystemJacobianCache` 重新引入；不把一次求值的输入暗藏为长期缓存先决条件。
  - 实测结论：`VersionedCacheSlot<Value, Sources...>` 把依赖集合放进类型参数,快照是
    `std::array<MultibodyStateVersion, sizeof...(Sources)>`,以定长快照直接比较,无分配、
    无查表、无间接层;热读取零 `std::any`／`void*`／`dynamic_cast`／`variant`／虚函数,
    也零 vendored 值类型。槽布局由 G27 工作区**类型**冻结——类型不能被追加成员,强于运行期
    表「拒绝追加」。已提交快照用 `std::optional` 表达冷槽,不拿版本 0 当哨兵:全新状态五个
    版本都是 0,零快照会与之比中,把默认构造的值当成算过的结果交出去。可变入口在交出引用
    **之前**丢弃快照,因此被放弃的重算留下的是过期槽而非「标记为新鲜的半写缓冲区」。
    类型参数只保证声明源与槽的新鲜度比较一致,不能证明声明覆盖计算器实际读取的全部输入;
    G27 以真实冷热上下文对照和重算计数验证绑定。提交只允许出现在成功重算之后,该调用顺序由
    G25 求值器封装并测试,本槽不重复建立状态机。
  - 判别力：常驻测试覆盖冷槽拒读、相关与无关版本变化、重算前作废、放弃重算、槽与状态隔离、
    预分配值地址稳定及构造、复制和移动边界；实施期扰动不进入仓库或长期路线。

- [x] **G24 — 验证版本依赖与新鲜度机制**
  - 产物：每个缓存槽保存其真实源版本快照，并直接比较 q、v 或相关参数版本；不建立 ticket
    图、通用依赖图或每参数机械分裂的版本体系。
  - 正确性门：用合成的类型化值与计算器验证同版本热读、依赖版本变化后过期、无关版本
    变化不重算及重算次数；本 Goal 不声称尚未接入的真实 tree 缓存已经正确。
  - 完成门：机制能表达 G20 的语义根版本依赖集合，不把 Drake 的 q/v 共同失效当成永久契约；
    真实位置、速度与惯量的冷热上下文对照留在 G27。
  - 实测结论：G20 契约保留的 11 个缓存,其语义根依赖收敛为 **8 种不同的子集**;逐子集建槽,
    对五个源各跑一格,共 **40 格**。预期矩阵**逐行手写**(五个具名布尔字段,并注明契约缓存
    编号 #1、#3、#4/#9、#6/#7、#8/#12、#10、#11、#13),不从 `Sources...` 反推——槽用
    `Sources...` 算新鲜度,若预期也这么算,则无论声明对错都会一致,而声明正是本 Goal 要验的
    东西。每格用全新的 state 与 slot,依次断言:冷查询恰好算一次、紧接的热查询不重算、
    写入之后**先直接**断言 fresh/stale 且写入本身不触发任何重算、下一次查询按相关性 +1 或
    +0、再次查询不变；同一源再推进一次并重复检查，证明槽保存的是连续版本快照而不是
    「零/非零」脏标志。

    真实冷热上下文对照与重算计数承担。
  - 判别力：常驻矩阵覆盖依赖漏项、多项、全量重算、遗漏重算、q/v 共同失效及把连续版本
    退化为一次性脏标志；实施期扰动不进入仓库或长期路线。

  - 明确不做：首版单线程求值，不加锁或并发状态机；第一方测试覆盖重复查询、按需重算、
    失败后重试、版本只增及上下文隔离。
  - 实测结论：`EvaluateVersionedCacheSlot(slot, calculate)` 一个自由函数,把「查新鲜度 →
    取存储 → 计算 → 提交」这个顺序只写一处,而不是在 G27 的十一个绑定点各写一遍。它很短,
    因为 G23 已承担了难的部分:取存储时就丢弃了快照,所以计算抛出后槽自然保持过期且不可读——
    无需 `try`、无需回滚、也不为强异常保证复制整块缓存值,异常照原样上传。
    额外加了一道**状态守卫**:计算前后各读一次版本,不同则拒绝提交并抛 `std::logic_error`。
    守的是**全部五个**源而非仅声明的那几个——一个声明 `{q, FP}` 的槽,其计算器若误写 v,
    只比声明源会放行,而那正是「值按修改前的状态算、提交却盖上修改后的版本」这一陈旧值被
    标为新鲜的路径。
    「版本只增」的验收口径澄清为:**合法缓存求值不修改任何状态版本**;版本本身的单调推进
    由 G22 验证。
  - 守卫的证明范围(如实收窄)：它只能证明计算期间没有任何版本化源被写入。它**不**证明依赖
    声明完整,也不覆盖无版本的阻尼、弹簧、衬套、模型常量与外部输入——那些由 G27 的 const
    绑定、冷热对照与重算计数承担。首版单线程,比较与提交之间不加锁或状态机。
  - 判别力:7 项临时注入全部被抓——提交移到计算之前、计算抛出时也提交、热查询也重算、守卫
    只比声明的源、完全不设守卫、跳过计算器直接提交、守卫比错对象。

G01 → G02 → G03 → G04 → G05 → G06 → G07 → G08
    → G09 → ... → G45 → G46/G47 → G48 → G49 → G50
