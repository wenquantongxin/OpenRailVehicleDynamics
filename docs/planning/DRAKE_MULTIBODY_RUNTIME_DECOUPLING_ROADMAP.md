# Drake 多体运行时脱耦路书

本文件是 ORVD 当前唯一的实施路书。它把当前 Drake 脱耦基础工作拆成 17 个子目标、46 个原子 Goal。
每次 Goal 模式只执行其中一个 Goal；不得在执行过程中重新规划整条路线或顺手扩展范围。

## 当前状态

- 工作分支：`main`
- 当前阶段：可移植交付基础
- 当前 Goal：无；G46 已完成，本路书的执行边界止于 `G46`
- 产品代码状态：刚性树已成内部产品目标 `orvd_rigid_multibody_tree`，其对象集合与全部落位翻译单元动态一致且各一次；编译前沿无缺口，`systems::`、`CacheEntry`、`DependencyTicket`、`MultibodyTreeSystem` 全树归零。第一方运行时已落地状态布局、类型化参数存储、版本缓存与具名工作区；G29–G39 已接通模型中立的程序化建模、运动学、质量矩阵、逆动力学、模型力元、具名外力和 O(n) 前向动力学，G40–G45 已接通静态系统组装、RHS 桥、真实 CVODE 后端及接受/试算提交事务。G46 已完成安装/导出、离线依赖源码包、迁移消费者与 Linux/Windows 资格。
- 已验证平台：Ubuntu 24.04 + GCC 13、Clang 18，以及 Windows 10 + Visual Studio 2019
  16.11 / MSVC 19.29。三种编译器均已从锁定依赖源码构建或消费安装包并运行同一真实 CVODE
  程序；不由此扩张成逐位一致、其他 Windows 版本或其他编译器版本资格。
- 仓库外探针：只作一次性研究输入，不直接复制进产品

## 不再讨论的前提

- 采用方案 B：先 vendor Drake 刚性多体树与拓扑，再逐步替换。
- 产品只支持 `double`；运行期不保留自动微分或符号标量。
- 最终产品不链接 `libdrake`。
- Eigen、fmt、SUNDIALS CVODE、Ceres 是允许的外置第三方；G46 官方独立源码包同时携带
  实际产品依赖的锁版源码，这只是依赖供应方式，不形成第二条产品实现路径。
- 保留模型中立的系统组装层；首个推进后端是 CVODE。
- GZ18 与 wheel-rail-lab 的复杂模型迁移不参与底层接口塑形，也不在本路书实施。G46 完成后，
  根据届时仍在演化的真实消费者另建独立路书；当前不冻结车辆自由度、拓扑或力元清单。
- 后继迁移路书必须从真实缺口重新展开：当前 RHS 只承载 `[q; v]` 且显式无调用期外力，
  不含 Maxwell 等附加连续状态、接触温启动提示或事件状态。迁移刚体惯量时还必须显式区分
  质心惯量与 ORVD 关于体原点的单位惯量，不得逐字段照抄。高频接触若消费点 Jacobian 或
  空间加速度，先测量现有调用期临时存储，再决定是否增加模型绑定工作区。
- 条件良好的 `double` 跨实现连续量默认采用 `1e-8` 相对误差；近零量使用按单位声明的绝对
  限；旋转使用 `1e-8 rad` 的 SO(3) 测地角。代数恒等式、有限差分、迭代求解和病态问题
  按各自误差来源另定判据，不把 `1e-8` 用作万能阈值。
- 不保存数值金标、输出快照、文件哈希或平台结果档案。
- 可信本地生成器产生的探针输入采用宽松解析；只检查实际使用字段能否解析及维数是否正确。
- 不提供旧名称、旧格式、旧接口或错误实现的回退兼容。

## 仓库外原型的处理规则

仓库外已存在可运行的启动器、参考发射器与缓存探针。它们**既不整文件迁入，也不盲目逐字重写**：

1. 先由 Goal 确定主线的长期接口，再逐函数审查仓外实现。
2. 只有脱离旧协议、脱离硬编码场景、脱离探针目录结构的**纯算法片段**可以选择性采用，并按第一方工程规范重构。
3. 现有启动器把场景定义、线协议、比较判定和进程管理混在一个文件里，不得整体复制：G06 吸收场景语义，G07 重建比较职责，G08 吸收缓存事实。
4. 主线测试承接必要知识后，仓库外探针整体删除，不归档、不留压缩包或软链接。

## Goal 模式规则

每个 Goal 必须满足以下格式：

```text
Goal GNN — <明确的功能名称>

前置 Goal：
唯一产物：
允许修改：
明确不做：

完成门：
1. <可执行、可判定>
2. <可执行、可判定>
3. <可选第三项>
```

执行纪律：

1. 一个 Goal 只产生一个逻辑产物；直接测试和必要说明随产物一起完成。
2. 默认在同一工作分支连续推进，一 Goal 一个聚焦提交；不为 46 个 Goal 创建 46 个分支。
3. 每次开始前读取本路书中的 Goal 定义和直接前置产物，不重新审议已定路线。
4. 完成门全部通过才标记完成；失败就在当前 Goal 内修复，不用兼容层绕过。
5. 若发现必须改变已接受架构，停止当前 Goal，先单独形成明确的新决策。
6. 构建产物、日志、临时观测、性能输出、金标和哈希不进入 Git。
7. 探索性测试用完即可删除；保护核心语义的短测试长期保留。

  - 隔离门：两个状态实例可引用同一不可变最终模型，但不共享状态或版本；修改其中一个

  - 实测结论：版本源恰好五个——广义位置、广义速度、全部固定坐标系位姿、全部刚体惯量、

    看见新版本；这不是并发同步机制。
    版本计数耗尽分支经公开 setter 理论可达,但常规测试无法实际覆盖:须先完成
    2⁶⁴−1 次成功写入再发起一次；不为这一条直白分支增加生产测试钩子。
  - 判别力：常驻测试覆盖五类成功写、同值重写、失败原子性、三类无版本参数和双实例隔离；
    实施时的错误类别、双推进、提前推进与遗漏推进扰动均会使测试失败，扰动本身不入仓。

## 子目标 9：实现固定类型缓存

- [x] **G23 — 实现通用类型化版本缓存槽**
  - 产物：运行时基础层提供由值类型、版本快照与新鲜度组成的预分配槽机制；它不引用

  - 完成门：热读取不经字符串、`AbstractValue` 或运行时类型擦除；模型最终化后由接入层
    组成的槽布局冻结，不能追加。
  - 边界：具体位置、速度、惯量和 Jacobian 工作区归 G27 刚性树接入层；带调用期外力的
    articulated-body force/forward-acceleration 结果直接计算或使用调用期工作区，逆动力学
    的规定加速度同样只作调用参数；
    其中 Jacobian 工作区指跨节点 `H_PB_W`，不把 G33 首版直接计算的
    `BlockSystemJacobianCache` 重新引入；不把一次求值的输入暗藏为长期缓存先决条件。
  - 实测结论：`VersionedCacheSlot<Value, Sources...>` 把依赖集合放进类型参数,快照是
    `std::array<MultibodyStateVersion, sizeof...(Sources)>`,以定长快照直接比较,无分配、
    无查表、无间接层;热读取零 `std::any`／`void*`／`dynamic_cast`／`variant`／虚函数,
    也零 vendored 值类型。槽布局由 G27 工作区**类型**冻结——类型不能被追加成员,强于运行期
    表「拒绝追加」。已提交快照用 `std::optional` 表达冷槽,不拿版本 0 当哨兵:全新状态五个
    版本都是 0,零快照会与之比中,把默认构造的值当成算过的结果交出去。可变入口在交出引用
    **之前**丢弃快照,因此被放弃的重算留下的是过期槽而非「标记为新鲜的半写缓冲区」。
    类型参数只保证声明源与槽的新鲜度比较一致,不能证明声明覆盖计算器实际读取的全部输入;
    G27 以真实槽的 fresh/stale 矩阵和冷热上下文值对照验证绑定；精确重算次数已由 G25
    对同一求值器验证。提交只允许出现在成功重算之后,该调用顺序由 G25 求值器封装并测试,

- [x] **G25 — 实现惰性原位缓存求值**
  - 产物：冷计算、热读取和失效后原位更新的求值器。
  - 完成门：冷槽恰好计算一次、热查询不重算、失效后只在请求时重算；只有成功计算才提交

    隔离留在 G27。

    取存储 → 计算 → 提交」这个顺序只写一处,而不是在 G27 的十一个绑定点各写一遍。它很短,
    因为 G23 已承担了难的部分:取存储时就丢弃了快照,所以计算抛出后槽自然保持过期且不可读——
    无需 `try`、无需回滚、也不为强异常保证复制整块缓存值,异常照原样上传。
    额外加了一道**状态守卫**:计算器正常返回后比较计算前后的版本,不同则拒绝提交并抛
    `std::logic_error`。守的是**全部五个**源而非仅声明的那几个——一个声明 `{q, FP}`
    的槽,其计算器若误写 v,只比声明源会放行,而那正是「值按修改前的状态算、提交却盖上
    修改后的版本」这一陈旧值被标为新鲜的路径。
    「版本只增」的验收口径澄清为:**合法缓存求值不修改任何状态版本**;版本本身的单调推进
    由 G22 验证。
  - 守卫的证明范围(如实收窄)：它只能证明**成功提交路径**在计算期间没有写任何版本化源。
    若计算器自身抛出,原异常直接传播且槽保持过期,但求值器不诊断或回滚它此前产生的状态
    副作用。守卫**不**证明依赖声明完整,也不覆盖无版本的阻尼、弹簧、衬套、模型常量与
    外部输入——那些由 G27 的 const 绑定与冷热值对照承担。首版单线程,比较与提交
    之间不加锁或状态机。
  - 判别力:7 项临时注入全部被抓——提交移到计算之前、计算抛出时也提交、热查询也重算、守卫
    只比声明的源、完全不设守卫、跳过计算器直接提交、守卫比错对象。

    候选**确实**静态链接 landed tree（那就是产品），不能写成「连 vendored copy 也没有」；
    它不能做的是把 installed 共享库也装进同一个地址空间——两者导出同一批 `drake::` 符号。

    **声明的动态装载闭包**只有一个答案：无论依赖在 CMake 中怎样写，共享 Drake 要么出现在按
    当前平台规则解析出的闭包中，要么没有。

    失败而不是「无可查即通过」，未解析节点同样失败。它不声称识别静态 `libdrake.a`、运行时

    路径。判别力由一个四情形驱动长期看守，每一例都断言退出非零**且诊断确为该情形**——
    `WILL_FAIL` 只看退出码，产物不存在也会被算作「通过」。四例：确实加载 Drake 的参考发射器
