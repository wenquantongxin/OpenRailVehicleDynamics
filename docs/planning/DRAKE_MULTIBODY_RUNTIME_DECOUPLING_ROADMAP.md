# Drake 多体运行时脱耦路书

本文件是 ORVD 当前唯一的实施路书。它把项目拆成 18 个子目标、50 个原子 Goal。
每次 Goal 模式只执行其中一个 Goal；不得在执行过程中重新规划整条路线或顺手扩展范围。

## 当前状态

- 工作分支：`main`
- 当前阶段：正式实施前的基础设施收口
- 当前 Goal：`G14`
- 产品代码状态：尚未开始
- 仓库外探针：只作一次性研究输入，不直接复制进产品

## 不再讨论的前提

- 采用方案 B：先 vendor Drake 刚性多体树与拓扑，再逐步替换。
- 产品只支持 `double`；运行期不保留自动微分或符号标量。
- 最终产品不链接 `libdrake`。
- Eigen、fmt、SUNDIALS CVODE、Ceres 是允许的外置第三方。
- 保留模型中立的系统组装层；首个推进后端是 CVODE。
- GZ18 在模型中立运行时稳定后接入，不参与底层接口塑形。
- 连续量以工程相对误差 `1e-3` 为主；近零量使用按单位声明的绝对限；旋转使用 SO(3) 角度。
- 不保存数值金标、输出快照、文件哈希或平台结果档案。
- 可信本地生成器产生的探针输入采用宽松解析；只检查实际使用字段能否解析及维数是否正确。
- 不提供旧名称、旧格式、旧接口或错误实现的回退兼容。

## 仓库外原型的处理规则

仓库外已存在可运行的启动器、参考发射器与缓存探针。它们**既不整文件迁入，也不盲目逐字重写**：

1. 先由 Goal 确定主线的长期接口，再逐函数审查仓外实现。
2. 只有脱离旧协议、脱离硬编码场景、脱离探针目录结构的**纯算法片段**可以选择性采用，并按第一方工程规范重构。
3. 现有启动器把场景定义、线协议、比较判定和进程管理混在一个文件里，不得整体复制：G06 吸收场景语义，G07 重建比较职责，G08 吸收缓存事实。
4. 主线测试承接必要知识后，仓库外探针整体删除，不归档、不留压缩包或软链接。

## Goal 模式规则

每个 Goal 必须满足以下格式：

```text
Goal GNN — <明确的功能名称>

前置 Goal：
唯一产物：
允许修改：
明确不做：

完成门：
1. <可执行、可判定>
2. <可执行、可判定>
3. <可选第三项>
```

执行纪律：

1. 一个 Goal 只产生一个逻辑产物；直接测试和必要说明随产物一起完成。
2. 默认在同一工作分支连续推进，一 Goal 一个聚焦提交；不为 50 个 Goal 创建 50 个分支。
3. 每次开始前读取本路书中的 Goal 定义和直接前置产物，不重新审议已定路线。
4. 完成门全部通过才标记完成；失败就在当前 Goal 内修复，不用兼容层绕过。
5. 若发现必须改变已接受架构，停止当前 Goal，先单独形成明确的新决策。
6. 构建产物、日志、临时观测、性能输出、金标和哈希不进入 Git。
7. 探索性测试用完即可删除；保护核心语义的短测试长期保留。

## 子目标 3：建立模型中立验证基础

- [x] **G06 — 定义模型中立场景与观测契约**
  - 产物：只覆盖当前验证所需的场景、拓扑、状态、激励和观测类型。
  - 完成门：角度、四元数、长度、力和力矩语义分离；无车辆概念；不发展成通用配置语言。

- [x] **G07 — 建立跨进程观测比较台架**
  - 产物：Drake 参考发射器、进程启动器、量纲化比较器和受控扰动自检。
  - 完成门：现场生成输入并经管道比较，不落盘参考输出；合法控制臂通过；对参考输出注入超过 `1e-3` 的已声明扰动必须失败。

- [x] **G08 — 测得真实缓存失效语义**
  - 产物：读取位置与速度运动学缓存 `serial_number` 与 `is_out_of_date` 的模型中立探针。
  - 完成门：重复求值后两者保持新鲜且序号均不变；改 `v` 或改 `q` 后两者均过期且序号在重求值前不变——Drake 当前只能整段取用可变 `q/v`（源码 TODO 明示），共同失效是参考实现的保守现状，不是 ORVD 的永久要求；过期后按需分别重算：先求位置仅位置序号严格递增、速度仍过期，再求速度后恢复新鲜；修改一个 Context 不影响另一个；任一语义不符返回非零。序号只判「不变」或「严格递增」，不锁定绝对值、缓存索引或恰好加一。
  - 明确不做：不假定存在质量矩阵缓存条目——`CalcMassMatrix()` 每次填写结果，只复用位置运动学、复合体惯量、跨节点 Jacobian 与反射惯量等下层缓存。不把某个模型的缓存条目数量写进路书。不以 `description()` 字符串作为稳定身份；探针钉死在固定 Drake 版本上、只服务参考端，其所用的缓存条目访问器不得成为 ORVD 接口。

## 子目标 4：确定 Drake 源码边界

- [x] **G09 — 建立逐文件源码处置清单**
  - 产物：每个候选文件标记为 vendor、自研、仅参考、丢弃或禁入的语义清单。`forbidden` 与 `discard` 分列：前者违反既定架构边界、闭包触达即失败，后者只是当前用不到、将来可重新裁决。
  - 完成门：不以数量阈值代替边界；明确排除 geometry、FEM、plant、contact、solver 和 deformable；记录固定 Drake 来源与许可证。
  - 明确不做：前缀规则只用于**负向**类别禁令；不设 `vendor_prefix` 之类的正向前缀，否则上游新增依赖会自动获准，「未分类边直接失败」随之失效。

- [x] **G10 — 建立现场源码闭包解析工具**
  - 产物：参数化的 include、生成头和链接支撑闭包工具。
  - 完成门：从源码和处置清单现场计算；未分类边、禁入边与未满足依赖三者分开报告且各自失败；不读取冻结列表或绝对路径。
  - 阶段关系：本 Goal 验收的是「解析器能正确发现并拒绝边界违规」，不是「边界已经干净」。未修改的上游必然存在 `element_collection.cc → deformable_body.h` 这条禁入边，真实闭包因此必然返回非零——该边由 G15 消除，边界最终干净由 G19 把关。不得用 `WILL_FAIL`、忽略禁入边或虚拟删边把它伪装成通过。

- [x] **G11 — 建立 vendor 边界编译探针**
  - 产物：把准入集合暂存后逐个真实编译、并链接产出对象的探针。
  - 完成门：源码 HEAD 与清单声明的固定 commit 一致；只暂存清单准入的文件，编译器看不到其他 Drake 源码；用 C++23 与真实 `-c`，成功须伴随非空对象；单个翻译单元失败后继续尝试其余；关闭链接垃圾回收后仍能暴露欠缺；不使用空返回替身证明语义；输出仅用于当次决策，不落盘符号表、符号数或允许列表。
  - 阶段关系：本 Goal 的链接只覆盖**当次编译成功的子集**，不冒充完整边界；全部翻译单元编译通过与全对象强制链接由 G17 用同一机制验收。当前多数翻译单元因清单裁掉标量机制而无法编译，这是 G16 的对象，不以通过数量作为任何 Goal 的完成证据。

## 依赖与并行规则

默认关键路径：

```text
G01 → G02 → G03 → G04 → G05 → G06 → G07 → G08
    → G09 → ... → G45 → G46/G47 → G48 → G49 → G50
```

允许的有限并行：

- G08 完成参考语义后，可与 G09–G11 的源码边界工作并行。
- G18 可与 G15–G17 的编译工作并行，但 G19 必须等两边完成。
- G37–G38 可并行准备，G39 汇合。
- G46 与 G47 可并行，二者都完成后才能开始 G48。

除上述情况外，Goal 模式按编号顺序执行，避免后续 Goal 反向塑造前置接口。
