# 轨道车辆动力学迁移：讨论与裁决账本

## 文档职责

本文件记录 OpenRailVehicleDynamics 承接轨道车辆动力学能力过程中，逐轮讨论形成的事实、分歧、
裁决和待决问题。它回答“为什么这样决定”，但不定义实施顺序、当前任务或完成门。

- 已接受且具有长期架构约束的决定，另行形成架构决策记录（ADR）。
- 已具备实施条件的决定，转入 [MIGRATION_ROADMAP.md](MIGRATION_ROADMAP.md)。
- 尚待核实的技术观察，写入 [MIGRATION_OBSERVATIONS.md](MIGRATION_OBSERVATIONS.md)。
- 本文件保留逐轮讨论、WRL 提交 SHA、工件路径与数值摘要，作为设计来源和历史考古；这些锚点
  不得转化为 ORVD 产品配置、运行时身份、数值金标或完成门。

## 项目负责人的总规划、宏观想法与偏好

### 总体目标

将 `wheel-rail-lab` 中已经由 IRW 与 GZ18 多工况验证的 Drake 轨道车辆多体动力学能力，迁移、
重构并精简到 OpenRailVehicleDynamics。目标不是复制原仓库，而是保留已验证的物理知识，形成
依赖方向清楚、模型中立、可维护、可验证的第一方实现。

### 已明确的工作偏好

1. **先裁清接口，再按原子 Goal 快速迁移。** G47–G72 已完成；后续
   Goal 仍须由项目负责人逐项授权，启用后不重复证据考古或扩建无消费者框架。
2. **以真实消费者校验抽象。** IRW 和 GZ18 是已闭合程度较高的真实模型，应作为能力来源和
   验证消费者；不为了迁移方便而预造没有消费者的通用框架。
3. **迁移知识，不照搬组织结构。** 优先提取物理公式、坐标合同、状态语义和验收经验；不直接
   搬运 Drake `Diagram`、车型专用运行器、硬编码状态索引或历史兼容路径。
4. **共性能力下沉，车型参数留在车型层。** 轮轨接触、力元扳手、轨道几何等共性公式应进入
   模型中立设施；轴重、结构尺寸、PRELOAD 等车型身份不得变成共性魔数。
5. **重构与精简是迁移本身的一部分。** 允许根据 ORVD 的现有运行时、模型和积分器合同重新
   划分职责，不把“与旧工程目录相似”当成目标。
6. **G01–G46 是已完成的底座，不是车辆迁移方案。** 后续设计应消费现有公开 API 和工程规则，
   同时以真实缺口判断是否扩展底座。

### R005 — 收口力元状态、阶段一消费者与工程分层方向

- 日期：2026-08-03
- 背景：项目负责人进一步质疑 `specialized_suspension` 的自明性，希望理解 Maxwell 附加状态与
  普通悬挂的差别，并要求车型、求解器、控制器、产品应用和科研实验具有长期清楚的工程位置。
- 讨论：普通并联弹簧—阻尼可由当前位移和速度代数求力；Maxwell 串联弹簧—黏性本构满足
  `dF/dt = K·v - (K/C)·F`，当前力依赖加载历史，因此每通道需要一个附加连续状态。二者在车辆
  物理层级上同为悬挂力元，只在本构状态需求上不同。旧 CVODE 路径在每个试算状态上经 Drake
  系统图共同求普通悬挂、Maxwell、轮轨和主动转矩，再返回完整状态导数；ORVD 可用静态编译次序
  和预分配扳手缓冲直接表达同一数学流程。动力学必需扳手不能关闭，可关闭的是冗余审计重建和
  序列化。控制算法与轮端执行器也必须分层，科研工作流不能反向依赖或污染产品库。
- 裁决：形成 PREF-018 至 PREF-021、DEC-008 与 DEC-009。阶段一先 GZ18 后 IRW；主路径先
  CVODE，串行闭合后同阶段准入 OpenMP，采样保持和 Radau3 后置。迁移中不采用
  `specialized_suspension` 名称，具体力元按物理本构命名。迁移路书仍未启用。
- 证据入口：WRL `scripts_cpp/drake_sim/src/specialized_suspension.cc`、
  `continuous_maxwell_lateral_damper.cc`、`scripts_cpp/irw/src/irw_cvode_driver.cc` 与
  `irw_simulation_runner.cc`；ORVD 第一方工程约束、ADR-0002 与 ADR-0003。
- 待决：复合连续状态与类型化力计划的最终 API；车型/资源/场景的安装布局；严格 JSON 的解析
  依赖与引用规则；1 kHz PID 的权威参数/事件身份及 SIMPACK RT 复现门。

  IRW 的每组轮对由轴桥、左轮和右轮三个刚体组成：轴桥本身具有自由体角速度，两个轮分别通过
  转动副保存相对轴桥的转角和转速。把八个轮速压成一个 `V0/R0`，或另存八份车轮绝对角速度，都会
  丢失冻结 H3 状态或建立第二权威。轴桥虽提供左右轮共享站位，却不是轮轨扳手的当然施加体。
- 裁决：形成 DEC-035。公共启动记录只在刚性轮对车型显式选择公共轮速生成器；IRW 不携带该对象，
  自由轴桥角速度、八个轮—轴相对关节状态和八个 Ball-RPY 状态分别按名写入 `q81/v74`，两个
  Maxwell 状态按名写入 `z2`。车轮惯性角速度由多体运动学合成，不在记录中重复保存。
- 证据入口：WRL `irw_afs_state_adapter.cc` 与 H3 `full148` 状态；ORVD G66 IRW 车型记录、G67
  `ResolvedStartupState`、随包 H3 资产及初始上下文装配门。
- 收口：G67 已完成两轮全新构建自检并原子落地；G68／G69 才解析真实型面、接触人格并把八个轮轨
  接口逐名绑定到八个车轮体。G67 未加入接触历史、电机或控制状态。

### R023 — 绑定 IRW 型面与接触人格

- 日期：2026-08-10
- 背景：G67 已提供 H3 的轮轨逻辑标识和已解析启动状态，G68 需要把这些身份解析为真实 S1002／
  UIC60 型面与冻结接触参数，同时避免复制 GZ18 的整套资产装配代码。
- 讨论：两车型共享同一数值接触核、轨距基准推导和资产合法性检查，但轮径、车轮型面预处理及
  侧滚横垂输运是承重差异。公开任意人格构造器会把车型身份变成调用方可混搭参数；把 IRW 工厂
  放进低层轮轨库又会反转配置依赖。来源中的 EEC 字面量在十几位后略有不同，但其物理关系同为
  `1/0.55`，不值得形成第二条运行路径。
- 裁决：形成 DEC-036。车型层保留 `AssembleGz18WheelRailContact` 与
  `AssembleIrwWheelRailContact` 两个闭合公开入口，配置实现私有复用资产加载、身份／角色核对、
  UIC60 轨距基准和左右模型构造。S1002 采用本项目自包含、升序 1000 点 JSON；供应商文件仍只作
  本地科研互操作输入，不入库。
- 证据入口：近期 WRL `s1002_profile.gen.h` 与 IRW 接触配置、ORVD 随包 S1002 JSON、
  `verify_irw_wheel_rail_contact_binding` 及迁移安装消费者。
- 收口：IRW `0.1 mm` 源横坐标重离散形成 1300 个左右镜像控制节点，启用态侧滚横垂输运抵达
  真实接触求值；静态 S1002/UIC60 两侧均形成有限正接触。G68 不伪造轴桥与独立车轮运动学，
  八轮具名车体接线继续由 G69 完成。

### R024 — 接通 IRW 独立车轮接触拓扑与 RHS

- 日期：2026-08-10
- 背景：G68 已闭合 IRW 的 S1002/UIC60 接触人格，但 GZ18 专用场景外壳和“站位载体就是受力
  车轮体”的旧力计划不能表达四个轴桥、八个独立车轮和八个轮—轴转动副。
- 讨论：冻结 WRL 同时使用两种角运动：材料点速度与自旋蠕滑取实际车轮绝对角速度，蠕滑参考的
  车轮俯仰转速则取轴桥俯仰速率减具名关节速率。H3 轴桥体基还相对非旋转物理轮型基固定旋转
  `diag(1,-1,-1)`；若直接把体基当轮型基，S1002 会倒置并使八轮接触归零。该安装变换必须右乘
  到载体姿态，不能通过修改 H3 机械姿态或引入车轮自旋相位补偿。
- 裁决：形成 DEC-037。通用力计划在串行准备阶段分别取得载体和实际车轮运动，并只在独立轮接口
  读取具名一维转动副速率；并行区继续只消费每接口不可变输入和独占槽。GZ18／IRW 的闭合 C++
  工厂是车型拓扑唯一权威，机械 JSON 不重复保存接触关系；所有权外壳原子改为车型中立名称。
- 证据入口：WRL `irw_simulation_runner.cc`、`track_geometry.cc`、`carrier_kinematics.cc` 与
  `wheel_rail_contact_system.cc` 的冻结换基和俯仰转速组合；ORVD
  `WheelRailContactForcePlan`、`AssembleIrwContactScenario`、真实 H3/R300
  `verify_irw_contact_rhs` 及迁移安装消费者。
- 收口：四份轴桥投影历史、八份接触工作区和八个车轮体扳手已进入有限 157 维 RHS；实际车轮
  Jacobian 的广义力、虚功和加速度增量闭合，单轮关节速率扰动只改变对应直接接口，1／2／4／8
  线程结果逐位一致。同一冻结 H3/R300 初态下八轮均为单斑，ORVD 相对 WRL 的逐轮
  `Q/N/Tx/Ty` 最大差为 `1.184/1.184/0.026/0.024 N`；该仓外来源核对不转成产品金标。G70 才开始
  CVODE 被动短窗和时间域响应。

### R025 — 收口 IRW 多斑观察与轻量积分统计

- 日期：2026-08-10
- 背景：G70／G71 侦查确认冻结 IRW A/B 长窗曾出现峰值双斑，而 G58 首版资格观察在第二个斑
  出现时拒绝；这会让正确的多斑动力学在最昂贵的离线重放阶段失败。项目负责人同时要求主线只
  增加轻量积分日志，不建设能量 API 或复制影子分支的性能框架。
- 讨论：ORVD 接触几何和正式结果面可表达 16 斑，RHS 已确定性累加全部返回斑，因此单斑限制只在
  观察层。冻结 WRL 最多保存 16 个候选、正式输出最多 4 斑；A/B 运行选择 `all_patches`，全部
  正式斑进入动力学，常规 CSV 仍选择最大法向力主斑。现有 SIMPACK SBR 的每接口 5 个斑槽只是
  当前工件通道形状，不是厂商求解器普遍上限。约 `3.659 s` 的 7 轮事件是某接口零斑；A/B 的
  `peak_patch_count=2` 是另一项拓扑统计，不声明二者发生于同一时刻。
- 裁决：形成 PREF-033 与 DEC-038。ORVD 观察面发布统一 Track-T 的总力及总 `Q/N`，并逐斑保存
  局部 `N/Tx/Ty`、接触点、Track-T 力和接触系角；不同局部接触系的 `Tx/Ty` 不直接相加，宽表
  仅保留明确标注的最大法向力主斑便利列。积分器按需查询累计成功内步、普通／线性求解器 RHS、
  误差测试、非线性迭代／收敛失败、线性建立和 Jacobian 次数；不装回调、不计时、不额外求值状态。
  G70 不建立储能／耗散 API。SBR 仅在 `tmp/` 本地只读提取，不进入 Git 或物理身份。
- 证据入口：WRL `rwc_core` 的候选／正式斑容量、A/B `all_patches` 运行与最大法向力主斑 CSV；
  ORVD `WheelRailContactModel`、`WheelRailContactForcePlan` 与 CVODE 推进器；MD-013／014。
- 收口：本轮先关闭 G70 前置观察和统计能力。超过 WRL 4 槽或当前 SBR 5 槽时，逐斑跨实现比较
  只报告参考工件不可表达，不截断 ORVD 动力学结果；G70 的后续实施与结果见 R026。

### R026 — 完成 IRW 被动 10 ms 首次时间推进

- 日期：2026-08-10
- 背景：G69 已把 H3 IRW 的四个轴桥载体、八个独立车轮和 157 维 RHS 接通，但尚未经过 CVODE
  时间推进；G71 的 30 s 首次硬核对标不能同时承担接线排错和长期传播判断。
- 讨论：既有 GZ18 资格运行器包含可共用的原子发布、密集输出、离线观察和端点接线闭合，但其
  装配工厂、代表体、不平顺和积分容差均是车型专用身份。共用部分只能下沉为不安装的私有内核，
  GZ18／IRW 各自以薄配方冻结差异，不能扩成任意车辆公共仿真接口。IRW A 层使用显式空不平顺、
  BDF 最大二阶及 `1e-7 / 1e-9 / 1e-8 / 1e-6` 的 rtol/q/v/z 容差。
- 裁决：G70 按上述私有分层完成。多斑观察发布统一 Track-T 总力和逐斑局部量；积分器只发布累计
  数值工作快照；每样本悬挂／轮轨功率列退出资格运行器，虚功只在终点接线门计算。
- 证据入口：真实 H3/R300 `orvd_irw_dynamics_qualification` 10 ms 工件；冻结 WRL A 层 100 µs
  输出；SIMPACK A 层 0.5 ms Realtime 输出；`verify_irw_dynamics_qualification`。
- 收口：一次连续推进得到 101 个 100 µs 观察点，其中 21 个是 SIMPACK 原生 0.5 ms 序号；终点
  广义力、虚功、`qdot` 和两个 Maxwell 导数闭合。四轴横移／摇头在该短窗与 SIMPACK 保持舍入
  量级差，轮轨力差异如实保留给 G71 的完整 30 s 图形与统计。G70 完成，暂停于 G71 开工前。

### R027 — 完成 IRW 被动 A/B 两层 30 s 资格

- 日期：2026-08-10
- 背景：G71 已完成无轨道不平顺 R300 的 A 层资格；G72 需要在完全相同的车辆、H3 启动、
  R300 线路、积分器、容差和采样时钟上只增加冻结 AAR5，并以逐点增量关闭 IRW 被动阶段。
- 讨论：B 层使用 P179 横／垂各 `6904` 点、共同域 `[0,1249.83] m` 的冻结 AAR5。第一方 JSON
  逐点保留来源 binary64、两端零段和已烘焙的淡入／淡出，不裁剪、不重生成随机谱，也不二次施加
  包络。A/B 用同一最终 Release 二进制重跑；不平顺增量先逐点计算
  `Δeir=(ORVD_B-ORVD_A)-(SIMPACK_B-SIMPACK_A)`，再分别统计各轴横移和摇头。
- 裁决：G72 完成。同站位 `100–450 m / 0.01 m` 比较中，B 层 ORVD—SIMPACK 横移均方根／最大值
  最差为 `6.83/44.85 µm`，摇头为 `21.35/78.64 µrad`；`Δeir` 对应最差值为
  `6.47/46.71 µm` 与 `21.36/78.48 µrad`。同时间峰值仍为
  `180.0 µm / 125.2 µrad`，且近期 WRL—SIMPACK 同样保留该量级站位传播差异，因此不得把
  同站位资格扩写为同时间高精度闭合。阶段一在“两车被动宏观响应”范围闭环；轮轨力高精度闭合、
  接触安全和 IRW 控制不在本轮结论内。
- 证据入口：P179 冻结 AAR5 点列、SIMPACK A/B 原生工件、近期 WRL A/B 工件、同一 ORVD Release
  A/B 资格运行及仓外逐轴图表。A 层观察序列与 G71 工件逐字节相同；B 层没有长期轮轨失联，已知
  约 `3.659 s` 的短暂七轮事件仍只作拓扑观察。完整进程墙钟为 A/B `2146.37/1108.49 s`，只说明
  本次 AMD Ryzen 9 9950X3D 执行，不外推为跨机性能结论。
- 收口：G47–G72 已完成，阶段一被动迁移闭环；暂停于 G73 开工前。
