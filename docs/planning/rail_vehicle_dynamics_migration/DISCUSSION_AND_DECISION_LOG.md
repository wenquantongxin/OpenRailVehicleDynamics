# 轨道车辆动力学迁移：讨论与裁决账本

## 文档职责

本文件记录 OpenRailVehicleDynamics 承接轨道车辆动力学能力过程中，逐轮讨论形成的事实、分歧、
裁决和待决问题。它回答“为什么这样决定”，但不定义实施顺序、当前任务或完成门。

- 已接受且具有长期架构约束的决定，另行形成架构决策记录（ADR）。
- 已具备实施条件的决定，转入 [MIGRATION_ROADMAP.md](MIGRATION_ROADMAP.md)。
- 尚待核实的技术观察，写入 [MIGRATION_OBSERVATIONS.md](MIGRATION_OBSERVATIONS.md)。
- 本文件保留逐轮讨论、WRL 提交 SHA、工件路径与数值摘要，作为设计来源和历史考古；这些锚点
  不得转化为 ORVD 产品配置、运行时身份、数值金标或完成门。

## 项目负责人的总规划、宏观想法与偏好

### 总体目标

将 `wheel-rail-lab` 中已经由 IRW 与 GZ18 多工况验证的 Drake 轨道车辆多体动力学能力，迁移、
重构并精简到 OpenRailVehicleDynamics。目标不是复制原仓库，而是保留已验证的物理知识，形成
依赖方向清楚、模型中立、可维护、可验证的第一方实现。

### 已明确的工作偏好

1. **先裁清接口，再按原子 Goal 快速迁移。** 当前 G47–G55 已形成待启用路书；在项目负责人明确
   设置当前 Goal 前不搬代码，启用后不重复证据考古或扩建无消费者框架。
2. **以真实消费者校验抽象。** IRW 和 GZ18 是已闭合程度较高的真实模型，应作为能力来源和
   验证消费者；不为了迁移方便而预造没有消费者的通用框架。
3. **迁移知识，不照搬组织结构。** 优先提取物理公式、坐标合同、状态语义和验收经验；不直接
   搬运 Drake `Diagram`、车型专用运行器、硬编码状态索引或历史兼容路径。
4. **共性能力下沉，车型参数留在车型层。** 轮轨接触、力元扳手、轨道几何等共性公式应进入
   模型中立设施；轴重、结构尺寸、PRELOAD 等车型身份不得变成共性魔数。
5. **重构与精简是迁移本身的一部分。** 允许根据 ORVD 的现有运行时、模型和积分器合同重新
   划分职责，不把“与旧工程目录相似”当成目标。
6. **G01–G46 是已完成的底座，不是车辆迁移方案。** 后续设计应消费现有公开 API 和工程规则，
   同时以真实缺口判断是否扩展底座。

### 尚未裁决的宏观问题

- G47–G55 已定义 GZ18 被动短窗的原子完成门；IRW 续篇、轨道不平顺、长窗科学运行和何时形成
  阶段一闭环，仍须由后续真实消费者单独拆分。
- 控制器、正式长窗输出、OpenMP、Radau3 与采样保持均不在 G47–G55；它们的先后顺序和各自
  完成门仍待后续路书裁决，不得借本批次顺手带入。
- PREF-002 中 Radau3 的产品实现来源，以及采样保持究竟属于接触更新还是积分器合同。
- PREF-010 的 40/50/60 m 现行语义和替代方案。
- 模型中立规范参数如何生成两端输入，哪些 SPCK 拓扑或格式字段仍须人工维护。
- `experiments` 如何只消费公共 API，以及 Python 环境和仓外结果的可复现边界。
- 1 kHz 简单 PID 的控制器级身份已闭合；仍待定义迁移后的同身份 SIMPACK Realtime 长窗车辆门，
  不得与 P179 的 100 Hz 人格混算。
- 根目录 `mbs_simpack/` 已允许公开分发；仍须形成逐资产来源说明和厂商材料负清单。
- 第一方许可主体、版权行、附加使用授权的法律措辞，以及首次公开发行时锁定的统一转换日期。
- 首批公开输出合同继续挂起；坐标、单位、采样时钟、聚合和文件格式均未裁决。

以上问题不阻塞 G47 启用，但不得由本批次路书隐含回答，也不得提前创建没有消费者的产品结构。

### R005 — 收口力元状态、阶段一消费者与工程分层方向

- 日期：2026-08-03
- 背景：项目负责人进一步质疑 `specialized_suspension` 的自明性，希望理解 Maxwell 附加状态与
  普通悬挂的差别，并要求车型、求解器、控制器、产品应用和科研实验具有长期清楚的工程位置。
- 讨论：普通并联弹簧—阻尼可由当前位移和速度代数求力；Maxwell 串联弹簧—黏性本构满足
  `dF/dt = K·v - (K/C)·F`，当前力依赖加载历史，因此每通道需要一个附加连续状态。二者在车辆
  物理层级上同为悬挂力元，只在本构状态需求上不同。旧 CVODE 路径在每个试算状态上经 Drake
  系统图共同求普通悬挂、Maxwell、轮轨和主动转矩，再返回完整状态导数；ORVD 可用静态编译次序
  和预分配扳手缓冲直接表达同一数学流程。动力学必需扳手不能关闭，可关闭的是冗余审计重建和
  序列化。控制算法与轮端执行器也必须分层，科研工作流不能反向依赖或污染产品库。
- 裁决：形成 PREF-018 至 PREF-021、DEC-008 与 DEC-009。阶段一先 GZ18 后 IRW；主路径先
  CVODE，串行闭合后同阶段准入 OpenMP，采样保持和 Radau3 后置。迁移中不采用
  `specialized_suspension` 名称，具体力元按物理本构命名。迁移路书仍未启用。
- 证据入口：WRL `scripts_cpp/drake_sim/src/specialized_suspension.cc`、
  `continuous_maxwell_lateral_damper.cc`、`scripts_cpp/irw/src/irw_cvode_driver.cc` 与
  `irw_simulation_runner.cc`；ORVD 第一方工程约束、ADR-0002 与 ADR-0003。
- 待决：复合连续状态与类型化力计划的最终 API；车型/资源/场景的安装布局；严格 JSON 的解析
  依赖与引用规则；1 kHz PID 的权威参数/事件身份及 SIMPACK RT 复现门。

### R006 — 收口配置源、控制器边界、SIMPACK 参考源与型面分支晋级条件

- 日期：2026-08-03
- 背景：项目负责人当时接受模型中立参数源、受限配置、科研 Python 边界、同进程 C++ 控制和轮对

- 背景：项目负责人确认 `mbs_simpack/` 可公开分发、许可主体暂时留白、首批公开输出合同继续

  静默用作黄金语料、1 kHz PID 证据入口和旧 36 斑型面表时效性的复核问题。
- 讨论：WRL 已正式固定 `nlohmann/json 3.12.0`（MIT），控制器参数、不平顺规格与归档均有
  真实消费者；C++ 产品没有 YAML 解析器，Python YAML 冻结器反而需要处理科学计数法被读成
  字符串或整数的隐式类型问题。ORVD 若在启动期只解析一次严格 JSON 并立即转成不可变领域对象，
  既保留用户可配置性，又不把配置解析带入右端热路径。R46 提交 `f0f8052` 已用同一次 10 ms
  SIMPACK Realtime 正向运行资格化 1 kHz 简单 PID 的 11 个事件边界、10 个零阶保持区间、8
  通道控制状态、转矩与控制功；P179 的 100 Hz 优选 PID＋普通电机代理三平台 30 s 结果是更难
  的系统级旁证，但不是同一控制人格。0714 的 36 斑表早于当前完整等弧长重扫＋第二 C2 实现；
  P016 的 0.1 mm 路线虽有局部小幅改善，却因步长来源和算法语义均不对应 GZ18 活动身份而未晋升，
  不能改写为“结果全面恶化”。
- 裁决：形成修订后的 DEC-010 至 DEC-012，以及 DEC-014、DEC-015。配置真源改为严格、版本化
  JSON，待首个真实加载器出现时才准入 `nlohmann/json`，不提前建空依赖。这里记录的“不可变”
  后由 R010 收窄：`TrackGeometry` 保持不可变，`VehicleDefinition` 明确允许装配前由 C++ 修改。
  `mbs_simpack/` 作为
  自建参考模型随仓公开分发；第一方许可采用 BSL 1.1 延迟转 Apache-2.0 的方向，但在许可主体
  留白期间不生成正式许可。已解析启动状态在类型、模式、目录、构建目标和测试引用上与期望输出
  隔离。首批公开输出合同继续保持 UNKNOWN，不因本轮配置裁决而默认形成。
- 证据入口：WRL `scripts_cpp/CMakeLists.txt:149`、`README.md:93`、提交 `39cf7ba`、`ba3a335`、
  `f0f8052`、R46 `R46_ACCEPTANCE.json`；GZ18 P016/P017 外置报告；MariaDB 官方 BSL 1.1 文本与
  Apache Software Foundation 的 Apache License 2.0 正式文本。
- 待决：第一方许可主体和精确附加使用授权；严格 JSON 的最终模式/路径；1 kHz 同身份长窗车辆
  门；用当前 P017 第一性实现重算 36 斑几何表；首批公开输出合同。

### R008 — 审阅并收口 GZ18 首批迁移路书

- 日期：2026-08-03
- 背景：Claude 以 ORVD `ef1c1438fa1c5815375dbad60eabb0e3e64d9542` 和 WRL
  `d7e272df8c29a2074d70eee7cd5a24cfede78d83` 为只读基线起草 G47–G55；项目负责人要求 Codex
  对抗性审查、保留 WRL SHA 历史证据，并让主线保持快速、轻盈、失败即响。
- 讨论：复核纠正了 GZ18 拓扑为 17 体、7 自由体、2 焊接、8 转动副，确认 10 个 1 kg 占位体
  计入质量；GZ18 有 2 路带连续力状态的横向串联弹簧—黏性阻尼和 4 路限幅抗蛇行阻尼。源数据
  同时存在已由 `diag(1,-1,-1)` 转换的 marker 与直接采用 Drake 数值的焊接／转动副父帧，不能
  批量翻转。ORVD 当前 CVODE 使用 `CV_NORMAL`，WRL 接触提示路径使用 `CV_ONE_STEP`，因此提示
  必须在每个内部接受端点重算并推进 candidate，而不是只在公开目标更新。轨道不在车辆树中，
  轮轨力在物理上是外力，但由编译计划根据试算状态自有求值，不开放调用期力入口。
- 裁决：接受九 Goal 主顺序并形成 DEC-016 至 DEC-023。站位投影原语进入轨道库，迁移期观测留到
  端到端纵切；`[q;v;z]` 与真实 GZ18 力元同一纵切；接触先串行，OpenMP 后置；接受步提示采用
  accepted/candidate 两份事务；G55 使用 `10 ms` 和仓外同站位 `0.1 mm/0.1 mrad` 宏观门。
  讨论账本和观察簿继续保留 WRL 提交、工件和历史数值，产品配置、运行身份和完成门不得依赖它们。
  提交后的两轮独立自检又补齐了超高正号、力元完整扳手与预载参数槽、启动身份与偏移符号、
  `{s,s_dot,dt}` 接触提示、多根连续分支、自旋蠕滑判别、短窗采样及八轮启动支承门；这些都是产品
  语义和 fail-fast 合同，不新增黄金轨迹、哈希门或常驻来源审计设施。
- 证据入口：本轮对 WRL `gz18_vehicle_builder.cc`、`gz18_marker_frames.cc`、
  `continuous_maxwell_lateral_damper.cc`、`anti_hunting_damper.cc`、CVODE 驱动与 ORVD
  `multibody_model`、`system_assembly`、`integrators` 的只读复核；本路书各 Goal 的完成门。
- 待决：Radau3、采样保持、OpenMP、IRW、控制器、不平顺、长窗和公开输出合同均保持后续范围。

### R009 — 启用路书并收口 G47 的开工裁决

- 日期：2026-08-03
- 背景：项目负责人明确授权启用迁移路书并开始 G47。Claude 完成 G47 开工侦查，
  提出十一项困惑点请求裁决。
- 讨论：侦查发现全路书 10 处「允许修改」中只有 G47 一处点名 `libs/track_geometry`，
  由此提出「是否需要给 G48–G55 批量补授权，否则 G47 必须一次冻结全部下游消费面」。
  另发现四条完成门在「所有夹具纵坡为零」时同时塌陷，以及三处结构上不可证伪的断言：
  侧滚角的往返恒等是浮点恒等式；缓和段端点一阶导连续在 Hermite 混合下是 `0 = 0`；
  站位投影的正交条件在距离极大值处同样成立。
- 裁决：形成 DEC-016 的十一项。要点：「允许修改」是当前 Goal 边界而非公共接口永久冻结，
  后续消费者窄幅裁决后扩展同一模块，故不批量放开 G48–G55；G47 不接收站位速度与步长，
  预测由上层做后只传一个种子；投影判据用通式 `F`、`F'`、`F''`，不把「横移超过曲率半径」
  当成一般三维判据；接缝过渡不隐式复刻也不整体删除，改写为声明的类型化几何区间；
  缓和段位置无初等闭式，改用构造期确定性数值求积并单列误差预算。
- 证据入口：本轮 Claude 对 ORVD 的 `CMakeLists.txt`、`cmake/OrvdFirstPartyTargetPolicy.cmake`、
  `cmake/OrvdProductBoundaryGate.cmake`、`multibody_rigid_pose.h`、`tests/CMakeLists.txt`
  与 WRL 轨道几何、姿态与投影实现的只读复核；Codex 的逐项裁决。
- 待决：无阻塞 G47 的待决项。

### R010 — 收口 G49 车型记录的 C++ 可变性与验收门

- 日期：2026-08-04
- 背景：G49 首版装配已落地；对抗复核发现原惯量门没有读取装配结果的完整转动惯量，同时路书把
  所有类型化配置笼统称为不可变对象，与科研用户需要在 C++ 中修改车型记录的用法冲突。
- 讨论：严格 JSON 只负责文件到记录的一次转换，不必把返回值封成不可变对象。`VehicleDefinition`
  作为普通值记录可直接构造或在加载后修改；装配器读取调用时快照、生成独立模型且不保留引用。
  原六质点与记录内往返检查代码较长，却没有触达模型完整惯量块，属于证据多而判别力弱。
- 裁决：保持 `VehicleDefinition` 公开可变；以三向非零质心、三个非零惯量矩阵非对角元的合成体
  直接核对装配后完整 6×6 质量矩阵，并以非零转动副阻尼和非共线三分量轴运动学验证装配器真实
  消费字段；真实 GZ18 的八个转动副另行声明正 y 轴。
  路书只约束本机、本地代码智能体，不限制科研用户调用公共 C++ 接口。项目负责人同时明确允许
  非盈利用户使用、修改与再分发第一方代码；正式许可主体与法律文本仍待落地。
- 证据入口：G49 `VehicleDefinition`、通用装配器、`verify_gz18_vehicle_assembly` 与项目负责人本轮
  裁决。
- 待决：正式许可证主体、法律文本与统一转换日期；G50 尚未授权进入。
