# 轨道车辆动力学迁移与重构路书

本文件是 OpenRailVehicleDynamics 现行唯一的车辆动力学实施路书。它把从 GZ18 首次短窗纵切、
GZ18 不平顺长窗、IRW 被动迁移，到 IRW 100 Hz 全状态控制与最小产品闭包的主线拆成 15 个子目标、
36 个原子 Goal（G47–G82）。每次 Goal 模式只执行其中一个 Goal；不得在执行过程中重新规划
整条路线或顺手扩展范围。

本路书只约束本机、本地代码智能体的实施顺序与提交边界，不限制安装后的公开 C++ 接口如何被
科研用户组合、修改或扩展；软件使用与再分发边界由许可证政策单独规定。

「为什么这样决定」记在 [DISCUSSION_AND_DECISION_LOG.md](DISCUSSION_AND_DECISION_LOG.md)，
只读事实与开放问题记在 [MIGRATION_OBSERVATIONS.md](MIGRATION_OBSERVATIONS.md)。本文件只回答
「做什么、按什么顺序、怎么算完成」，不重复裁决理由。

## 不再讨论的前提

以下条目已在裁决账本中收口，实施期不重新审议。括号内为账本编号。

- 产品动力学路径只支持 C++；不迁移、不兼容 `pydrake`。Python 只能进入默认不构建、不安装的
  科研实验层。（PREF-001、PREF-023、DEC-013）
- 阶段一先 GZ18、后 IRW，两车通过共同被动纵切才算阶段一闭环。G55 只是 GZ18 首次 10 ms
  闭环；G56–G72 才补齐 GZ18 激励长窗和 IRW 两层被动工况。（DEC-008）
- 主积分路径是 CVODE BDF 加逐次右端状态求值。IRW 当前承重的 30 s 被动参考同样采用
  `rhs_state_eval`，每次 RHS 试算态重算接触；历史接触采样保持不是被动主线。有限周期事件只随
  G76 的 100 Hz 全状态控制作为真实消费者进入。Radau3 是独立的可选第二后端，尚无产品实现来源
  裁决，不进入 G47–G82 的完成门。（PREF-002、DEC-009、OBS-023）
- 不迁移 WRL 的通用静平衡与 PRELOAD 求解器。随库资格化实例是「60 km/h 已解析移动启动状态」；
  用户可修改 `V0` 研究其他严格正向速度，轮速按既有启动等效滚动半径等比例变化；只有轮轨型面、
  接触策略、载荷工况或轨型偏移改变时才须同步更新该半径。零速与反向启动拒绝；近零速及随后
  跨零速的轮轨物理尚未资格化，首版不作有效性承诺。
  该状态不得称为「60 km/h PRELOAD」。
  （PREF-005、PREF-006、PREF-017、DEC-007）
- 随库 GZ18 示例从直线、水平、零超高且无轨道不平顺的区段启动；通用科研入口允许非平直研究，
  基础轨道定义区间外由定义边界切线直线延长，但这些组合不自动继承参考工具对齐资格。
  （PREF-016、PREF-028、DEC-006、DEC-028）
- 轮轨算法采用近期固化的共同主体：共同法向接触角、三维互穿长度优先且解析弦长作基线、无形状修正、自然三次型面、
  局部接触半径参考速度、二次泊松比 Kalker 系数表、Kalker 1982 自适应网格。自旋蠕滑率照常计算
  并参与 FASTSIM 切向应力，只把**直接接触斑蠕滑矩**规定为 `Mz = 0`。`pk_beta` 与
  其他未选人格分支不迁入。解析弦长不是可选择的长度人格：它始终由当前几何量计算，三维长度解析成功
  才覆盖；解析失败时沿用基线并从同一次求值报告回退，不增加第二次状态求值、热路径日志、字符串格式化
  或动态分配。（PREF-003、DEC-005、OBS-017）
- 开发期保留受控低层策略以复现两车各自的 WRL 行为：车轮型面预处理，以及型面/轨道侧滚 y-z 输运。
  策略实现下沉到轮轨低层，车型层按类型化身份选择当前组合；不允许任意混搭，不恢复环境变量人格。
  单一晋级是带低角/高角直接证据的条件结果，不预设必然二选一，也不得退化为按接触角在线切换。
  （DEC-005 修订、OBS-033、OBS-038）
- 第一方算法按真实物理功能命名，注释以 QCH 所载理论的公式与物理语义为依据；不出现厂商对齐、
  调试、尝试闭合或开发期措辞，不出现厂商关节序号式命名。不迁移 `specialized_suspension` 这类
  含糊名称。（PREF-004、PREF-018）
- 车型定义、已解析启动状态、场景组合与控制器参数采用唯一当前形状的严格 JSON：字段名显式携带单位语义，
  拒绝重复键、未知键、缺失必填键、类型错误、环境变量替换与模糊路径搜索；启动期解析一次并立即
  转成类型化领域对象，右端热路径不接触 JSON DOM 或文件系统。`TrackGeometry` 自身不可变；
  `VehicleDefinition` 是供科研用户在装配前显式修改的 C++ 值，装配器只消费调用时快照。
  第一方 JSON 不携带数字模式／格式版本，也不按版本分派；结构变化必须同步全量修改，旧字段和缺失
  当前字段直接响亮失败，由 Git 历史承担追溯。

- 已解析启动状态只能作为产品输入，不是仿真输出期望。严格模式自然拒绝未定义字段；不为此再建

- 不固化黄金轨迹、历史结果哈希或逐位输出。与 WRL / SIMPACK 的宏观对比只在仓外临时运行，按物理量

## Goal 模式规则

每个 Goal 必须满足以下格式：

```text
Goal GNN — <明确的功能名称>

前置 Goal：
唯一产物：
允许修改：
明确不做：

完成门：
1. <可执行、可判定>
2. <可执行、可判定>
3. <可选第三项>
```

执行纪律：

1. 一个 Goal 只产生一个逻辑产物；直接测试和必要说明随产物一起完成。
2. 在 `main` 上连续推进，一 Goal 一个聚焦提交；不建分支，不 push。Goal 若显式拆成原子子步，
   各子步独立验证和提交，不混入后续子步的产品代码。
3. 每次开始前读取本路书中的 Goal 定义和直接前置产物，不重新审议已定路线。
4. 完成门全部通过才标记完成；失败就在当前 Goal 内修复，不用兼容层绕过。
5. 只为真实可达的失败模式或廉价的非法输入保留反例；不要求每条完成门配反例，也不把故意破坏
   产品源码、测试之测试或极端数值边界做成常驻门。
6. 若发现必须改变已接受架构，停止当前 Goal，先单独形成明确的新决策。
7. 构建产物、日志、临时观测、性能输出、金标和哈希不进入 Git；一次性探针用完即删。

**完成门的判别力要求。** 结构计数和总质量等检查可以抓到漏装、重复装配或占位体被误删，但不单独
承担跨实现忠实性证明。每个 Goal 还须至少有一项解析关系、几何/物理不变量或事务性质门。跨实现宏观比较只在仓外
临时运行，不将数据与结果带回主线。

## 子目标 18：建立线路与轨道设施基础

- [x] **G47 — 建立线路惯性系与轨道几何**
  - **前置 Goal**：无（消费 G01–G46 底座）
  - **唯一产物**：模型中立的 `libs/track_geometry`：线路惯性系、直线／Hermite 缓和／圆曲线、
    平面里程中心线、纵坡、超高、C² 接缝过渡、轨型系位姿与一阶运动学，以及局部站位投影。
    参数由类型化 C++ 值构造，不读文件。
  - **允许修改**：新建 `libs/track_geometry/`；根 `CMakeLists.txt` 的产品模块清单、安装目标与
    公共头安装循环；`tests/track_geometry/`、`tests/CMakeLists.txt` 与安装后消费者。
  - **明确不做**：不引入任何新第三方依赖；不读 JSON 或任何文件；不接多体、不接接触；
    不实现轨道不平顺、轨距加宽、轨底坡、钢轨型面倾角或公开输出合同；不接收运行期站位历史；
    局部分支种子由 G54 上层持有并逐接受端点更新。

  **坐标与量义。** 惯性系 `I`：`+x` 沿起点里程增加方向，`+y` 向右，`+z` 向下。
  `track_station` 是平面投影里程，故 `‖d[x,y]/ds‖=1`；`centerline_upward_grade>0` 表示上坡，
  `dz_I/ds=-grade`。无侧滚系 `T₀` 的 `x` 轴沿三维单位切向，`y` 向右，`z=x×y`。
  超高 `u=(p_right-p_left)·z_T₀`，`φ=asin(u/b_ref)`，`R_IT=R_IT₀·R_x(φ)`。
  后续装配器显式设置 `g_I=[0,0,+g]`，多体底座保持坐标中立。

  **几何与数值。** 缓和曲线采用曲率的 Hermite 三次混合，**不是回旋线**。无接缝的相邻剖面
  必须端值连续；声明的接缝窗口用匹配两端值、一阶导与二阶导的五次多项式。直线和圆曲线解析
  积分，缓和与接缝采用固定阶确定性求积；节点间距是显式精度参数。构造期允许分配，成功求值
  路径不扩容动态容器、不查名称、不写日志、不访问文件。位姿与一阶运动学同次返回，并满足
  `dR_IT/ds=[ω_IT]×R_IT`；中心线二阶导保持私有。

  - **完成门**：
    1. 圆曲线闭式位置与曲率、Hermite 内部点、接缝 C²、求积收敛、左右曲线镜像、定义域与超高
       约束均通过；解析、求积和有限差分分别使用对应容差。
    2. 非零曲率／航向／纵坡／超高夹具的 `R_IT` 九分量、正交性、行列式、超高符号和旋转率恒等式
       通过。
    3. 中心线竖向导数及轨型系纵轴竖向分量与正负纵坡的数值关系通过。
    4. 站位投影只做无历史的**局部分支跟踪**：窗口在节点分辨率下必须恰有一个严格内点极小根，
       且满足 `F'=0` 的残差门与 `F''>0`。窗口壁根不计入候选；没有唯一严格内点根或参数非法时
       失败。不提供全线搜索，同一节点区间内未被网格分开的多根不在完备性承诺内。

  说明：WRL 侧存在切向系 `z` 分量取 `-sinθ`、而中心线导数取 `+slope` 的符号不一致，因其四个
  内置预设纵坡恒为零而长期休眠；本 Goal 按上述坐标约定裁决，不沿用该休眠状态。WRL 源全局系
  与 `I` 逐轴同义，`diag(1,-1,-1)` 仅是其 Drake 世界系转换；产品不保留运行期外部坐标转换层。

  - **实测收口**：模块已安装导出，只公开依赖 Eigen；五个公共头均有自包含编译门，安装消费者
    能链接并求值。圆弧积分采用避免近数相减的半角形式，节点位置使用补偿累加。三个聚焦测试覆盖
    上述四门；dev 38/38、release 38/38、drake-reference 42/42 通过，未新增告警。

  半角系或省略支承矩，也不得把支承矩与端点 `r × F` 重复计算。侧滚元是基准端标记系 `x` 方向

  单列，不与 `q`/`v` 共用。

  广义坐标，也不是缓存；公开状态提交一次原子覆盖时间与全部块，失败则全部丢弃。G54 的内部接受步

       `P_absorbed = dU/dt + D`。侧滚线性空间本构中，几何角导数 `alpha_dot_geom` 与采用的
       `omega_x` 在有限姿态下不严格相同，因此准确边界为
       `P_absorbed = dU/dt + D + K·alpha·(omega_x − alpha_dot_geom)`；该有限姿态线性化余项必须
       单独重建，不得强行吸收到能量误差。串联弹簧—黏性元满足
       `P_absorbed = d(F²/(2K))/dt + F²/C`；无储能的限幅阻尼满足 `P_absorbed ≥ 0`。
       非线性限幅力律还须在原点、线性插值段、`±0.02 m/s` 边界和两端饱和区连续且满足奇函数性。
    5. 力元计划与参数所有权：每个真实实例在一次 RHS 中恰好消费一次；串联力元的状态导数由解析
       预言机覆盖。力元名一次解析为系统绑定的强类型索引，未知名称、跨系统索引和名称重排不得静默
       指向别的槽。两个上下文写入不同预载后互不污染；同步到积分器试算上下文后，真实 CVODE 纵切
       必须观察到同一预载。编译计划和 `VehicleDefinition` 均不持有可变预载值。
    6. 一次性来源核对：用仓外临时脚本或审计程序核对 28 个非零活动车辆力元的实例、端点、本构
       参数、启动参数槽位、状态维数与本构选择均已 all-and-only 迁入；同时明确核对并排除源中
       4 个已启用但名义力与刚度均为零、作用恒零的牵引杆。脚本和输出用后删除，不把源提交标识
       或数值清单变成产品门。

  侧滚 y-z 输运的**纯数学与类型化策略属本 Goal**，其真实消费者是手工构造的完整刚体运动学输入；
  真实线路位姿的获取与开关判断归 G53，核心里不得保留无人读取的布尔字段。该输运的合同是**部分施加**：
  三个偏移只作用于位姿阶段与轨侧接触角，蠕滑输入与接触点约化仍使用原始横移／侧滚／摇头量。这个
  非对称必须由类型或注释明确归属，并由 G52a 的数学夹具直接判别——施加一个纯滚动偏移会改变法向方向
  与切向合力，而法向力大小不变。启用态与关闭态的判别力来自「偏移是否被算出并送入位姿」，不是核心内
  的一个布尔分支。本 Goal 的合成消费者只证明核心合同，不得据此宣称随包型面与真实轨道已经接通。
  待两车均落地且专项晋级裁决移除最后一个车型绑定时，同一次改动必须删除相应策略；某一维只剩一个
  策略时连同选择层一起折叠。WRL 提交与工件可作为该决策的历史证据保留，但不进入产品配置、运行时
  身份或完成门。

  **参数按五类承载，这也是完成门 4 的分母**：一、共性物理参数（弹性模量、泊松比、摩擦律常数）；
  二、车型策略位；三、显式离散参数（型面弧长采样点数、形心积分细分数、横向分箱宽度、
  斑合并间隙阈值、FASTSIM 网格划分数、接触判据裕度、FASTSIM 自适应网格容差、两个型面预处理步长）；
  四、实现内部常量（斑数与分段上界、求根迭代次数与容差、求积阶数），由解析性质或
  结构测试约束，不为凑齐清单升格成产品配置；五、**资产派生常量**——由型面、轨距、轨距测量深度与
  轨底坡派生的量（左右轨型横向基准即属此类），必须在加载型面后按同一派生函数重算，不得抄冻结字面量；
  该类进入完成门 4 分母的是**派生公式与其输入**，不是某一次求解出的数值。
  第一到第三类作为显式配置项承载，不作为算法常量硬编码；其取值随车型策略身份绑定。
  软极值温度不在此列——它唯一的消费者是本 Goal 明确不迁的软极值形心。
  轨距与轨距测量深度是接触型面装配输入，由本 Goal 类型化承载；线路的钢轨参考横距是线路参考几何，
  不得冒充轨距。

  **参数边界**：参考配置里的 `n_int_delta=80` 不进入 GZ18 人格或完成门 4 的
  all-and-only 分母。近期 WRL 在共同法向模式下仍先计算旧的加权接触角候选，随后无条件以共同法向覆盖；
  `n_int_delta` 只控制这段被覆盖的旧计算。ORVD 直接构造共同法向，不复制这段无消费者循环。该轴由共同法向
  的解析与几何性质门覆盖，排除它是删除无效参数，不是把活动人格常数硬编码进实现。

  两项参数另有具名裁决。**FASTSIM 自适应网格容差**作为显式、必填、严格为正的配置项承载；参考实现
  在该值非正时回退到一个由网格划分数导出的表达式，而在当前划分数下该回退恰与已冻结取值位级相等——
  这个巧合不得被制度化，**非正哨兵回退不迁移**。**轨底坡**在参考实现中是两个独立字面量（接触侧与
  位姿侧，相差约 `1.6e-09 rad`）；G52 按两个具名用途原样承载，**不擅自归一**，是否统一留待真实消费者
  证明二者是同一物理量后单独裁决。

  **型面资产政策**：供应商 `.prw/.prr` 不进入 Git、不上传远端、不随
  安装包发布，只留在本地用于科研核对与向参考工具回灌验证。ORVD 随包发布**本项目自有、自包含、
  格式清晰的 JSON 型面资产**，它是运行时型面的唯一真源；项目不依赖 CONTACT，也不把其资产或代码
  引入依赖链。第一方型面设施须同时提供严格 JSON 读写、受支持的 `.prw/.prr` 读写，以及二者之间的
  **语义转换**；SIMPACK 互操作通路服务本地开发与验证，不进入接触求值热路径，也不得成为第二份运行时权威。
  转换验证比较坐标系、单位、角色与点列语义，不要求注释、空白、头字段顺序或字节级往返；测试只用
  临时生成的合成文件，仓内不得提交供应商型面或由其直接生成的固化夹具。不固化型面哈希、外部绝对
  路径或供应商文件名为运行身份。参考实现「读取点列后静默忽略全部头部变换」的做法不得沿用：未查明
  或未支持的非恒等变换必须响亮拒绝。

  正式 JSON 必须显式携带**型面角色、坐标轴与单位、有限且有序的点列**，按既有严格 JSON 纪律
  拒绝重复键、未知键、缺失必填键与类型错误。SIMPACK 互操作读写至少识别文件角色、长度单位、点块与已查明的变换
  声明，输出采用参考工具可导入的规范简式。已知的两处形状事实必须被合同覆盖：其一，供应商轮型文件
  声明了一个非恒等的数据顺序标志，参考实现忽略它而未出错只是因为那些点在文件内本就按横坐标升序，
  ORVD 不得以此为由继续忽略；其二，轨型点列的横向步长并非严格常数，不得用「首点加等步长」的算式
  假装是均匀网格来做 O(1) 查表。**合成夹具证明不了互操作读取器能读真实文件**，因此本 Goal 须另做一次仓外
  一次性核对：用本地真实供应商文件走一遍读入与语义转换，只判定是否被正确接受与解释，程序、输入与
  输出用后删除，不进 Git、不进完成门、不留数值。

    静平衡，也不把 P035 数值元组、外部路径或 SHA 抄进代码、测试、资产或数值金标。SIMPACK Type-80
    原生 `Tx/Ty` 是轨侧端点分量，与 ORVD 轮侧结果比较前须取负。ORVD 的轨型系 `+z_T` 向下，轮侧力为
    `F_w=Tx·t_x+Ty·t_y-N·n`；P035 平直轨道上 `T` 与惯性系同向，故正的世界竖向支承幅值为
    `Q=-e_{z_T}^T·F_w=N·n_{z_T}-Tx·(t_x)_{z_T}-Ty·(t_y)_{z_T}`；不得简化成 `N·cos(delta)`。P035 各原生通道独立按
    binary32 写出，按这些通道重建的 `Q` 使用物理容差而非逐位比较。

  - **完成门**（按上文分派到三个子步，全部通过才标记 G52 完成）：
    1. 接触力学性质门（与实现无共享代码）：**逐单元**切向应力不超过该单元的摩擦上界；切向合力不超过
       同一网格上摩擦上界的离散和乘以 `(1 + 1e-14)`。该限是按物理量声明的误差限，不是数值金标；
       实施期**只可收紧、不可放宽**，也不得为通过门而事后裁剪合力。上界由测试从单元输入独立重算，
       不依赖产品输出里的任何诊断累加量。对解析 `μ·N` 的求积偏差可另行报告，但不得作为判据——逐单元
       钳位的忠实实现在自适应网格上本就会略微越过解析 `μ·N`。**三个蠕滑量全部为零**时切向合力为零；
       只有平移蠕滑为零而自旋蠕滑非零是合法的纯自旋辨识点，必须仍产生非零切向力，以此证明自旋通道
       未被误删；`φ_z=0` 负对照不变。直接接触斑蠕滑矩数值恒为零，且该截断不改变自旋对 `Tx/Ty` 的影响。
       轮侧扳手须由法向力与两个切向分量独立重建，再与产品输出的规范扳手比对；轮侧与轨侧扳手搬到
       同一原点后合扳手为零。**不得只把产品输出取负再检查自身**——同点取负是接口合同，不单独充当物理证据。
    2. 型面与几何不变量：型面样条在节点处满足其声明的连续阶；两套预处理策略各自保持端点、
       顺序和显式步长合同；Kalker 表在原生节点处复现表值，域内插值有限、为正且落在相邻节点的
       局部包络内；车轮型面预处理的两个分支互斥由**构造期检查**保证——两个步长都非零的配置必须在
       构造期失败，而不是靠类型让该状态无法表达（无法表达的状态写不出反例，也就证明不了判别力）。
    3. G52 时点的无并行、无环境依赖基线：单接口数学核心在没有 OpenMP 头、编译定义和链接目标的
       环境中独立构建；以不同线程及阶段计时环境变量运行相同夹具，结果与控制流不变。参考实现的并行
       驱动整支、两处环境读取和构建侧无条件 OpenMP 链接均未随 G52 带入。**本条不是永久禁止产品使用
       OpenMP**：G59 已按 DEC-030 与 ADR-0006 作为独立 Goal 在 `orvd_forces` 的八接口批上恢复必需
       OpenMP 依赖，而单接口 `orvd_wheel_rail_contact` 数学核心仍保持上述串行语义。
    4. 一次性来源核对：用仓外临时程序核对已晋级算法轴、两处车型绑定策略、型面语义和前三类与第五类
       参数已 all-and-only 迁入；第四类由结构或解析性质门覆盖，不进入该清单。程序和输出用后删除，
       不保留数值人格哈希或快照。
    5. 资产引用与启动身份边界：运行时型面由**与文件格式无关的逻辑标识**绑定，再由安装数据根解析到
       随包 JSON。该解析路径上，标识含 `..`、路径分隔符或绝对路径一律拒绝，形如 `${NAME}` 的字面值
       不作环境变量展开；本门不预建通用搜索服务。该限制只约束**运行时资产解析**：开发期转换工具按
       设计接受调用方给出的任意路径，包括仓外绝对路径，二者是不同入口，不得互相套用。
       G51 启动记录中的轮型、轨型与轮轨策略标识必须 all-and-only 解析到真实加载对象并比对人格；
       任一不符都在建立接触上下文前失败。G51 的车辆级型面绑定与单一轨型竖向偏移是当前正确粒度，
       不得借本门拆成逐轮或逐侧字段。

## G55 之后的共同资格纪律

G56–G82 的长窗、跨实现与产品化工作共同遵守以下纪律；各 Goal 不再重复展开：

1. **长窗不进默认 CTest。** 默认测试只保留短解析夹具、装配、事务、守恒与真实消费者烟测。
   完整物理长窗由 Linux Release 本地资格运行承担；GCC、Clang 和 Windows 只要求短真实消费者、
   安装迁移与运行期闭包，不建立平台×车型×线路×控制器的笛卡尔矩阵。
2. **仓库不保存长轨迹和数值金标。** 场景配方、类型化输入合同和解析性质可进 Git；WRL／SIMPACK
   原始轨迹、完整统计、性能日志和哈希均在仓外生成。资格结论签收后，可在 README 或规划文档中
   保留少量可复核的主响应图与摘要表，但它们只是文档性结论，不能被产品、测试或后续运行反向读取为
   期望轨迹。原始长轨迹和全量中间工件按负责人的仓外保留口径管理。SHA 只可用于下载或搬运时的一次校验，
   不成为物理身份或完成门。
3. **时序与里程序列同时观察。** 每个 SIMPACK 对比工况都生成同时间和同站位两种视图。G60 为复现
   既有 `10 s` 激活证据，数值门仍按共同整数时间索引，且两端对应轴站位同时落入预登记窗口；其
   同站位视图仍须生成但只作诊断。从 G61 起，每轴分别投影到预先声明的公共站位格，并以同站位结果
   承担主门；只允许在相邻样本间线性插值。不移时、不滤波、不去均值、不拟合、不缩放，也不用
   结果相关网格补救覆盖不足。
4. **每个工况一张主响应图。** 主图使用四列对应 4 个轮对、四行依次对应轮对质心轨道横向位移—
   时间、轮对摇头角—时间、轮对质心轨道横向位移—轨道站位和轮对摇头角—轨道站位，共十六个
   子图；使用高分辨率横向大画布，不得把不同工况叠在同一主图。
   每个子图只含 ORVD 与 SIMPACK 两条曲线；确需保留具名 WRL 参考／控制列时最多三条。接触力或内部通道
   只在因果定位需要时另作诊断图，并继续遵守单子图两条、含 WRL 时三条的上限。相同响应量使用
   同一单位和可直接比较的坐标尺度，不使用双纵轴制造视觉重合。
5. **统计量不能替代曲线判读。** 4 个轮对逐一、逐段报告均方根、最大绝对误差和必要的误差分位；
   预登记阈值是定量目标和报警线，不是单独的否决按钮。阈值内且两域曲线合理可通过；越线但已完成
   物理归因的工况只形成有条件结论，须单独裁决；存在未解释偏差则阻塞。未越线也不能掩盖持续偏相、
   错误峰值或错误物理事件。
6. **精度与速度成对记录。** 每次 `5/10/30 s` 级运行同时记录精度工件和真实性能工件。分别定义
   `推进实时因子 = 模拟时长 / 动力学推进墙钟` 和
   `端到端实时因子 = 模拟时长 /（推进 + 观测 + 诊断 + 写出墙钟）`，不得混用。最低记录总墙钟、
   资格流水线四段耗时、线程／硬件／编译优化身份和外层峰值内存；求解器步数、RHS、误差测试、
   Jacobian 及线性／非线性迭代只在后端已有只读统计面时记录，不从样本数伪造。每个候选重复运行并
   报告波动，同时记录 CPU 频率／功耗策略。起步无轨道不平顺区通常快于进入激励后的区段，因而须
   另作实际分段性能剖析，不从短窗或前段线性外推全程；分段性能运行不得冒充一次连续科学轨迹。
   实时或快于实时是长期目标，不是尚未测量就写死的完成门。
7. **只观察五层承重因果链。** 依次为输入身份／激活站位／采样时钟，同时间／同站位的接触斑与
   八轮三向力，四个站位载体的质心轨道横向位移／摇头角，代表性构架／车体响应，最后是完整动力学
   残差与必要接线闭合。只有某层首次出现持续差异时才展开该层内部通道；能量、耗散和悬挂功率是
   误差较大时的归因工具，不为每个 Goal 新增公共 API 或常规输出，也不复制 WRL 的大列宽诊断表。
8. **输入资产与基础线路正交。** 不平顺是独立站位场，不改写 `TrackGeometry` 中心线；大型横／垂
   数组独立于场景 JSON，启动时一次加载成不可变对象，RHS 不读文件、不解析 JSON、不重新生成随机谱。
9. **观测先保持内部。** G58 的长窗观测只服务迁移资格；坐标、单位、时钟、聚合和文件格式到
   G80 才冻结为公开合同。此前不得因临时 WRL 输出方便而反向塑造公共 API。

### 精度—性能联合优化路线

性能优化从 G60 起与科学资格并行推进，但任何候选都必须在同一冻结输入上重跑上述时序／里程图和
承重统计。实验日志、剖析结果和临时轨迹留在仓外；只有被真实长窗证明有效且不产生不可接受物理偏差
的实现才进入产品。低风险的预分配、重复计算消除或数据布局修正可作为对应 Goal 前的聚焦修复；更换
积分器后端、改变接触更新时相、引入新的线性代数后端或扩大并行层级属于架构改变，必须先上呈裁决并
另设清晰实施边界。G60／G61 的必需产物是科学基线与真实剖析，不以必须找到加速方案为完成条件；
任何产品优化都单独形成聚焦实施边界，不夹入资格运行提交。

| 阶段 | 工作 | 收口条件 |
|---|---|---|
| 基线 | G60 以未调参的当前 Release 完整跑 `10 s`；G61 完整跑 `20 s`，另由明确标识的性能运行记录无激励、淡入、全幅、淡出和恢复各段耗时与可得的积分器计数 | 同时得到 SIMPACK 曲线、误差统计、热点占比和真实性能因子，不以早段速度外推后段，也不让性能停靠改变科学轨迹 |
| 单因素筛选 | 分别扫描积分器与容差、接触离散／更新周期、内存与重复计算、接触并行及线性代数路径 | 每次只改变一个承重因子；短跑只用于淘汰，入选项必须重跑完整资格窗 |
| 联合试验 | 将单因素有效项组成有限的精度—速度帕累托候选，不做所有开关的笛卡尔穷举 | 同一候选同时报告墙钟、积分器／接触计数、峰值内存及四个轮对的两域曲线；不能用局部函数等价代替闭环证据 |
| 长窗确认 | 在 G61、G63、G71／G72 和 G77 的 `16/20/30 s` 工况上复核入选组合 | 不同线路、车型和激励段均无未解释退化；硬件和编译身份明确，才可称为可复用优化 |

重点实验因子如下：

- **积分器。** 联合扫描容差、最大步长、非线性／线性求解和 Jacobian 策略；记录内部步数、RHS 与
  Jacobian 次数、误差测试失败和非线性收敛。容差变宽不保证更快，必须用实测识别非单调区间。
- **轮轨接触。** 对几何离散、积分点数、接触求值降采样、保持或插值策略做受控试验；这些变化会
  改变物理时相，只能作为候选人格对照，未经 SIMPACK／WRL 闭环核对不得成为默认执行路径。
- **内存与重复计算。** 优先消除可提前获知长度的容器扩容、每步对象构造、重复样条／几何准备和
  不必要拷贝；同时核对峰值内存、分配次数与缓存局部性，不能只优化孤立微基准。
- **并行与矩阵计算。** G59 的八轮接触并行是第一步；后续可测轴／转向架粗粒度、Jacobian／线性
  求解和 BLAS／LAPACK 等矩阵路径。接触 OpenMP 与矩阵线程必须防止过度订阅，并分别测单层与组合
  策略；没有真实收益就不扩大公共依赖或线程控制面。

WRL 早期提交提供了候选方向，但多数没有可复核的端到端倍数，不能直接当 ORVD 的性能金标：

- `5ba62b2` 引入钢轨廓形、样条与导数常驻缓存；`ef3332d` 继续做输出缓冲复用、FASTSIM 不变量外提、
  除法改写和接触几何三角运算简化。
- `b5955e1` 只把 `s_samples` 从 2000 下调到 1000；`887e91f` 才同时调整 `s_samples`、
  `n_int_centroid` 和 `n_int_delta`，并记录把 `sim_stepsize_s` 改为 `1e-4 s` 后反而明显变慢。
  两者都未留下足以量化或归因的端到端工件，因此须重新做联合实验。
- 较晚的 `1a366a9` C++ 记录在 `50 s`、60 km/h、Radau3、`all_patches` 工况下给出可复核量级：
  Release 串行相对 Python 为 `2.33×`，4／8 线程相对 C++ 串行为 `1.59× / 1.81×`；剖析显示
  轮轨接触约占一半、Drake Radau／前向动力学约占另一半。
  这证明优化上限不止八轮并行，也说明矩阵／积分路径必须以实测热点而非猜测推进。

项目负责人另有早期 WRL 并行运行达到实时或快于实时的历史观察，但上述 Git 提交没有保存足以独立
复核该结论的完整工件。路书将它作为可复现实验目标而非既成金标：在明确硬件、线程与亲和性、编译
器及 `-march`／LTO／PGO 等优化身份、冷／热启动、重复次数与波动、物理人格和精度曲线的前提下，
先以 `推进实时因子 ≥ 1` 为目标，再单列端到端实时因子；`-ffast-math` 等改变浮点语义的候选必须重跑
完整科学资格。未同时通过科学资格的更快运行不计入达成。

       八路零阶保持转矩继续由 `SystemRuntimeContext` 所有并进入 RHS。
    2. 控制器和调理器各自持有其递推所需的采样周期；装配期要求两者逐位相等且等于 `10 ms`，由该

       调理器仍各按一个完整 `10 ms` 递推记忆，不存在零步长分支。随后每次事件只消费该边界当前接受
       机械状态。
    3. 事件边界由整数序号乘共同周期生成，禁止累计 `t += 0.01`。现有
       `SystemContinuousStateAdvancer::AdvanceTo()` 负责精确停靠，事件成功提交后调用
       `SynchronizeAfterAcceptedContextChange()` 把保持转矩传入候选 RHS 并重初始化数值历史。推进到
       边界失败时，接受态仍在前一边界；到达边界后事件计算／校验失败时，机械时间与连续状态保留在
       当前边界而控制器状态、调理器记忆和保持转矩保持事件入口值，并封锁后续推进直至该事件成功；
       事件已提交而同步失败时不回滚、不重复递推，只封锁推进并重试同步。
    4. 真实 H3、R300、冻结 AAR5 的 `0.5 s` 短窗包含一次零作用时长初始化、`k=0..50` 的 51 次
       周期递推、50 个正时长保持区间和 `t=0..0.5 s` 的 51 个观察点；终点递推只形成零作用时长的
       控制审计记录，不重初始化求解器。逐事件核对请求转矩、调理后转矩、限制值／状态、控制器后态、
       调理器后态和保持区间；首次两次 `t=0` 输出与 P179 逐位闭合，后续闭环信号按同序报告而不以
       机械轨迹逐位相等冒充算法门。另检查宏观状态、接触和动力学残差有限，记录分段墙钟、接受步、
       RHS／线性 RHS，并核对 49 次非终点重初始化。SIMAT 上一通信拍只按 MD-015 分栏，不通过移时、
       输入缓存开关或第二套人格使其冒充本门。
