# 轨道车辆动力学迁移：观察、清单与开放问题

## 文档职责

本文件是 Codex、Claude 和其他审查者共同维护的迁移观察簿。它保存当前源码事实、只读盘点、
假设、反例和待验证问题，为讨论裁决提供输入。

本文件**不是**实施路书，也不自动授权代码改动。观察只有转入
[DISCUSSION_AND_DECISION_LOG.md](DISCUSSION_AND_DECISION_LOG.md) 并形成明确裁决后，才可进入
[MIGRATION_ROADMAP.md](MIGRATION_ROADMAP.md)。

## 协作维护规则

每项观察至少包含以下字段：

| 字段 | 要求 |
|---|---|
| 编号 | 使用稳定编号 `OBS-NNN`。 |
| 状态 | 以“已确认”“已裁决”“假设”“UNKNOWN”“已否证”之一开头；可在冒号后收窄适用范围。 |
| 观察 | 把源码事实、推断和建议分开写。 |
| 锚点 | 指向源码、测试、ADR、路书章节或可再生的只读来源。 |
| 影响 | 说明它可能改变哪项迁移裁决；不在这里下实施命令。 |
| 下一核验 | 给出最小、可判定的只读核验。 |

共同编辑时遵守以下边界：

- 没有证据的结论写 `UNKNOWN`，不以措辞强度替代证据。
- 当前事实直接更新；Git 历史负责追溯旧观察，不保留平行旧版本。
- 不把历史输出哈希、逐位一致或单次性能数字当成永久正确性门。
- WRL 提交 SHA、工件路径和历史数值可以保留为设计来源与反例考古；不得把它们升级为 ORVD
  产品配置、运行时身份、测试期望或完成门。
- 车型身份和共性公式分栏；不得由某一车型的数值反推共性魔数。
- 一次性探针和大型运行工件留在仓库外，本文件只保留可复核结论及来源入口。

## 本轮基线观察

### OBS-001 — ORVD 已具备可消费的模型中立多体底座

- 状态：已确认
- 观察：截至 2026-08-02 的只读基线 `dab87414c1f790c46028b179f3fa25829eba947c`，
  G01–G46 已完成。公共能力包括多体运行时、程序化多体模型、最小系统组装和 CVODE 推进；
  vendored Drake 刚性树是内部实现，不是公共 API。
- 锚点：
  - [已完成底座路书](../DRAKE_MULTIBODY_RUNTIME_DECOUPLING_ROADMAP.md)
  - [`libs/multibody_runtime/`](../../../libs/multibody_runtime/)
  - [`libs/multibody_model/`](../../../libs/multibody_model/)
  - [`libs/system_assembly/`](../../../libs/system_assembly/)
  - [`libs/integrators/`](../../../libs/integrators/)
- 影响：迁移应优先消费现有公共合同，而不是把 Drake Systems 层重新搬进产品。
- 下一核验：在确定首个车辆消费者后，逐项建立“需求—现有 API—真实缺口”矩阵。

### OBS-002 — 车辆迁移所需的多个产品层仍为空或只是最小纵切

- 状态：已确认
- 观察：`libs/forces` 与 `libs/equilibrium` 目前是骨架；`system_assembly` 只承载一个多体组件，
  连续状态固定为 `[q; v]`。现有系统到 CVODE 的桥明确采用无调用期外力路径。
- 锚点：
  - [`libs/forces/README.md`](../../../libs/forces/README.md)
  - [`libs/equilibrium/README.md`](../../../libs/equilibrium/README.md)
  - [`libs/system_assembly/include/orvd/system_assembly/system_instance.h`](../../../libs/system_assembly/include/orvd/system_assembly/system_instance.h)
  - [`libs/integrators/README.md`](../../../libs/integrators/README.md)
- 影响：真实轮轨接触、悬挂力元、附加连续状态和静平衡不能被假定为已有能力。
- 下一核验：由五组只读清单给出首个消费者的最小缺口，而不是先扩建通用框架。

### OBS-003 — 当前跨 Drake 资格是瞬时算子资格，不是车辆轨迹资格

- 状态：已确认
- 观察：现有独立进程参考台架在固定状态和输入上比较运动学、质量矩阵与动力学算子；它不推进
  车辆时间，也未覆盖静平衡、接触切换、控制事件或长窗相位。
- 锚点：
  - [`tests/drake_reference/`](../../../tests/drake_reference/)
  - [`tests/comparison/`](../../../tests/comparison/)
  - [ADR-0004](../../adr/0004-focused-dynamics-qualification.md)
- 影响：迁移后的车辆验收需要另建物理分层与时间轨迹资格，不能扩张现有测试结论。
- 下一核验：确定首个消费者后，列出必须瞬时比较和必须随时间比较的观测量。

### OBS-004 — 首个结构阻塞很可能是力与附加状态的所有权，而不是刚体树

- 状态：假设
- 观察：ORVD 已有刚体拓扑和动力学纵切，而 `wheel-rail-lab` 的真实车辆还消费接触扳手、
  悬挂力元、Maxwell 等附加状态、预载荷与更新时相。它们尚未映射到 ORVD 的模型数据、上下文、
  调用期输入和事件事务。
- 锚点：OBS-001、OBS-002，以及待完成的只读清单 A、B、C、E。
- 影响：若假设成立，最早的设计轮次应先裁决状态与力的合同，再讨论整车构建器。
- 下一核验：完成五组只读清单并用一个真实消费者做闭包检查。

### OBS-005 — 性能问题已知集中于轮轨接触总路径，内部主热点仍未知

- 状态：已确认
- 观察：`wheel-rail-lab` 的既有长窗记录显示轮轨接触总路径占主要墙钟，但当前证据不足以在
  几何搜索、法向接触、蠕滑和 FASTSIM 之间确定唯一首要热点。
- 锚点：`wheel-rail-lab` P057、P178、P179 外置工件及其 `perf_breakdown` 字段；ORVD 不保存
  这些历史输出作为产品门。
- 影响：迁移时应保留可测量边界，不能在没有分阶段剖析前先做并行化或缓存重构。G58 只记录每次
  资格运行的整体推进、观测及观测数据与元数据写入墙钟和缓冲规模，不设性能金标，也不把短窗墙钟
  线性外推到激励长窗。
- 下一核验：G59 在资格机器的真实代表片段上建立不新增 CVODE 停靠点的 `0.5 s` 分窗统计，分解
  接受步、RHS、八轮接触、差商 Jacobian、拒步、分配与峰值内存后再裁决并行。

### OBS-006 — 共同轮轨主体已裁决，两处差异暂作受控低层分支

- 状态：已确认
- 观察：项目负责人已裁决 ORVD 共享同一轮轨内核，研究人格不得平行进入，`pk_beta` 明确排除。
  当前 WRL 固化主线也已证实两车共同选择 `common_normal`、
  `interpenetration_3d`、`shape_correction=none`、自然三次型面、局部接触半径、二次泊松系数表、
  Kalker 1982 网格及直接 `Mz=0`。Claude 关于“GZ18 可能仍使用旧人格”的判断已经过时。
  但当前 WRL 仍有两项真实算法差异：IRW 开启轨道姿态/横垂运输而 GZ18 关闭；IRW 使用
  0.1 mm 源横坐标重离散并形成折线可见轮廓，而 GZ18 使用 0.5 mm 等弧长重扫和前后两条自然
  三次样条。项目负责人现决定在迁移和开发期保留这两处差异，以便分别对照 WRL 已固化记录；
  开发后期仅在直接低角/高角证据支持全局胜者时单一晋级。实现所有权必须下沉到轮轨低层的具名功能策略，上层车型组装只映射
  到两套已经验证的配对组合，不向普通配置暴露四格任意混搭，也不以车型名、厂商名或环境变量
  命名底层算法。跨轮轨几何、法向接触、蠕滑、轨道几何和车辆力元的完整“数学功能—共同主体—
  暂存分支—淘汰项—来源提交—车型参数”矩阵仍未建立。
- 锚点：[R003](DISCUSSION_AND_DECISION_LOG.md)；WRL 当前主线
  `scripts_cpp/generated/gz18_contact_config.gen.h`、
  `scripts_cpp/generated/irw_contact_config.gen.h`、
  `scripts_cpp/rigid_wheelset/src/gz18_startup_identity.cc`；IRW 提交 `a85f353` 与 GZ18 提交
  `912ea232` 均已选择 `shape_correction=none`。
- 影响：没有该矩阵就可能误搬默认值、研究开关或只为误差归因存在的备用公式；反之，把分支放在
  车型组装器内部又会复制轮轨算法并阻碍开发末期统一。
- 下一核验：建立只读算法分支清单，逐项写明数学功能、共同主体、两套冻结选择、淘汰项、车型
  映射和最小判别测试；为低层策略拟定物理自明名称，并建立防止第三套组合或环境变量覆盖的
  早拒绝门。条件晋级实验暂不进入未启用路书。

### OBS-007 — 积分器与接触更新时相是两个正交维度

- 状态：已确认
- 观察：CVODE、Radau3 描述连续状态推进方法；逐次右端状态求值、采样保持描述轮轨力何时重算
  或保持。PREF-002 给出了优先组合，但产品接口不能把两维压成一个含糊枚举。
- 锚点：[R002 宏观方向](DISCUSSION_AND_DECISION_LOG.md)、清单 B、清单 C。
- 影响：若不分层，求解器替换会静默改变接触物理时相，也无法解释拒步和接受步中的状态所有权。
- 下一核验：列出预期支持的组合矩阵，并分别定义试算、接受、拒步、重初始化和输出时刻；确认
  Radau3 是否需要第一方实现且不得引入 `pydrake` 产品依赖。

### OBS-008 — 首版启动产品是 60 km/h 已解析移动状态，不是通用 PRELOAD

- 状态：已确认
- 观察：WRL/SIMPACK 的 PRELOAD 会确定目标轮载；每次求解器初始化再把目标轮载转换为轨道
  微小竖向偏移并持久化。已有 GZ18 经验还表明静止与移动上下文的解析偏移不同。ORVD 首版不
  迁移通用静平衡与低速切向边界处理，只加载已经验证的 60 km/h 移动启动配置。配置至少需要
  携带静载荷、各力元名义力、轨道偏移、初始纵向速度 `V0`、能复现资格化轮速的启动等效滚动半径
  和相关启动身份。
  现有语境中的“PRELOAD”至少混用了
  四类不同物理量：悬挂名义预载力、每轮目标支承力、初始化解析出的轨道竖向偏移，以及静平衡
  位姿；移动启动还增加初始速度、轮速和内部力状态。未来字段必须拆名。随库示例的资格域是直线、
  水平、零线路超高、零不平顺；通用科研入口允许非平直外推，但不声称参考工具对齐。解析量仍需绑定
  车型、轮轨型面、轮轨算法分支和移动速度上下文。轨底坡或钢轨型面倾角属于轮轨几何，不是线路
  超高，必须分栏。
  GZ18 已有静止/60 km/h 解析轨道偏移分别为 `-0.0003057459272813503 m` 与
  `-0.0003055705255365684 m`，差约 `0.1754017448 µm`，直接否证“一个车型永远只有一个偏移”。
  静止值可保留为研究证据，但不进入首版可选启动配置。
- 锚点：[R004](DISCUSSION_AND_DECISION_LOG.md)、清单 E；WRL GZ18 P004、P033、P035
  只读工件在正式裁决前重新核对。
- 影响：“一车一配置”应落实为“车型定义＋具名启动状态”，而不是让车型名静默推出速度相关偏移。
  零速与反向启动必须明确失败；近零速及随后跨零速尚未资格化，不作物理有效性承诺。其他严格正向
  速度由用户只修改 `V0` 研究，轮速按既有启动等效滚动半径等比例变化，但不是资格化实例。
- 下一核验：G51 以车型／机械修订引用、载荷工况、启动方向、`V0`、启动等效滚动半径、轮对自旋轴、
  轨道偏移和内部力状态构成最小启动记录。轮轨型面、材料和低层算法策略仍由被引用的
  `VehicleDefinition` 权威承载，不在启动记录复制；轨道预设、曲线半径、不平顺、控制器、积分器、
  更新方式、日志和初始绝对里程也不成为启动键。线路几何对象只证明逐体站位在定义域内；随库示例
  另行证明自身满足 DEC-006 的资格域。

### OBS-009 — 车辆参数当前存在多个来源和覆盖优先级

- 状态：已确认：问题存在；目标所有权已裁决
- 观察：项目负责人指出 WRL 的 GZ18/IRW 组装值混合来自 SPCK、subvars 以及没有被 subvars
  实际覆盖的 SPCK 字面量。项目负责人现已选择模型中立的 ORVD 车型参数作为规范源，分别生成
  ORVD 消费配置和 SIMPACK `subvars`/受控输入；`subvars` 不再反向成为产品权威源。
- 锚点：[R006 与 DEC-010](DISCUSSION_AND_DECISION_LOG.md)、清单 D、清单 E；WRL
  `scripts_cpp/generated/irw_params.gen.h:8,14` 与 `scripts_cpp/generated/gz18_params.gen.h:8`
  已直接登记多来源身份。
- 影响：若直接复制当前优先级，ORVD 会继承隐式覆盖和厂商模型耦合；若一次抽取全部参数，又会
  形成中等规模的模型数据迁移任务。
- 下一核验：按刚体、标记、关节、力元、轮轨参数和启动量列出当前权威来源与覆盖结果；确定哪些
  物理参数可由规范源生成、哪些 SPCK 拓扑/格式字段必须人工维护，并为生成后两端的实际消费值
  建立字段级往返审计。

### OBS-010 — 正交组合仍需要显式兼容性合同

- 状态：已确认
- 观察：轨道平面几何、车型、速度、控制器、不平顺和积分器应独立建模和组合；但控制器只适用
  某些车型、启动状态依赖速度/接触身份、不平顺具有有效站位区间，因而“正交”不等于所有组合
  都已资格化。DEC-006 把直线、水平、零超高定为随库示例资格边界，同时允许科研入口显式外推。
  DEC-007 又规定首版只有 60 km/h 是随库资格化移动启动身份；这是证据范围限制，不是把
  “车型”和“速度”合并成一个永久不可分的领域对象。
- 锚点：[R002 宏观方向](DISCUSSION_AND_DECISION_LOG.md)、清单 B、清单 C、清单 D、清单 E；
  ORVD 当前最小系统边界见 `libs/system_assembly/README.md` 与
  `libs/system_assembly/include/orvd/system_assembly/system_assembly_description.h`。
- 影响：产品需要清楚区分可组合维度、声明的依赖和不相容组合，不应重新形成车型专用大预设。
  当调用者选择的速度没有对应解析启动身份时，应报告“缺少该速度的启动配置”，而不是把速度
  静默改成 60 km/h 或临时求平衡。
- 下一核验：建立“维度—输入—输出—依赖—不相容条件”只读矩阵，再决定系统组装 API。

### OBS-011 — 最小产品输出合同仍缺坐标和时钟定义

- 状态：UNKNOWN
- 观察：项目负责人希望移除 WRL 的误差归因观察器，首批只输出四轴横移与摇头、八轮三向轮轨
  力、接触斑数量和 IRW 电机输入转矩。各量的参考坐标系、正方向、采样时刻和斑聚合规则尚未
  形成产品合同。
- 锚点：[R002 宏观方向](DISCUSSION_AND_DECISION_LOG.md)、清单 A、清单 C。
- 影响：过早复制现有 CSV/NPZ 写出器会把调试字段和车型专用语义带入产品；过度删减又可能使
  用户无法构建自己的观察器。
- 下一核验：先把 WRL 相关代码分成“RHS 必需计算、首批产品输出、科研观察器、仅测试独立
  重建”四类；只从产品运行接线移除后两类。随后为每个首批输出写具名物理定义、单位、参考系、
  采样时钟和多斑聚合规则，并裁决用户扩展观察是库 API、示例层还是完全由调用者实现。

### OBS-012 — 已验证的性能技巧需要从旧所有权中剥离

- 状态：已确认
- 观察：WRL 历史实现包含 OpenMP 并行、接触点提示、预分配容器和工作区复用。这些技巧可能
  必须保留，但其当前代码位置、线程所有权和确定性口径不必适合 ORVD。
- 锚点：[R002 宏观方向](DISCUSSION_AND_DECISION_LOG.md)、OBS-005、清单 B、清单 C；WRL
  提交 `1a366a9`、`9d30784`、`ef3332d` 提供历史入口，现行 C++ 路径仍须从
  `rwc_core/src/contact_batch.cc`、`track_geometry.cc`、`fastsim.cc`、`contact_kernel.cc`
  重新盘点。
- 影响：整块复制会把 Drake Context 和车型运行器耦合带入 ORVD；完全重写而不盘点则可能造成
  数量级性能回退。
- 下一核验：为每项技巧登记所处热路径、数据所有者、生命周期、线程安全、分配次数、关闭反例
  和可再生收益，再决定迁移或重做。

### OBS-013 — IRW 的 40/50/60 m 是不同领域边界的混合呈现

- 状态：已确认
- 观察：初步只读核对已发现多套站位语义并存：AAR5 规格使用 `start_m=60`、`fade_len_m=40`；
  R300 轨道构造使用 50 m 初始直线和 50 m 缓和段；IRW 控制器又使用 50 m 的速度参考斜坡和
  曲线引导起点。另一份冻结 AAR5 身份还含 `txt_station_offset_m=100`、`start_m=160`、
  `fade_len_m=40`。这些数值不是同一个概念的四种写法。
- 锚点：WRL

### OBS-021 — 接触提示是接受步数值历史，不应直接冒充物理状态

- 状态：已裁决：所有权和事务由 G54 落地
- 观察：WRL 的逐次右端状态求值路径把每个唯一接触载体的已接受线路里程提示、提示速度和全体共享
  的步长提示保存在数值参数或驱动缓存中，并只在接受边界后推进。2026-08-02 的 GZ18 P057 与
  IRW A/B 30 s 正式工件均为 `numeric_parameter`、`stride=1`、`predictor=false`：三量虽仍维护，
  但 RHS 分支选择只消费 accepted `s`。它们不属于车辆
  物理连续状态，但也不是普通无状态缓存：拒绝的试算不得污染下一接受步，重初始化、复制上下文、
  并行车辆实例和回放都需要明确的种子、提交和清空语义。另一个 `state_eval_s_hint_cache_` 属于普通
  状态求值路径，不能
  与主 `rhs_state_eval` 接受提示混成同一状态机制。Claude 由此直接断言“接触不再是 `(q,v)` 的纯函数”仍过强；
  在唯一根场景中，若提示只改变求根初值而不改变收敛解，物理算子仍应与冷启动同义；多根场景中
  提示本来就负责维持连续物理解，任意冷启动可能合法选到另一根，不能强求全局同根。前者须由
  冷／热同义夹具证明，后者须由最近 accepted `s` 所隔离的局部邻域证明。
- 锚点：WRL `scripts_cpp/drake_sim/include/drake_sim/wheel_rail_contact_system.h` 的
  `accepted_s_hint_parameter_index_` 与驱动缓存，及
  `scripts_cpp/drake_sim/src/wheel_rail_contact_system.cc` 的 `seed_accepted_hints()`、
  `advance_accepted_hints_from_cache()`；ORVD [ADR-0003](../../adr/0003-abstract-advancer-cvode-first.md)
  与 `libs/integrators/README.md` 已覆盖连续状态及局部分支站位的接受／试算事务。
- 影响：G54 只迁移资格化力计算真实消费的 `s`，由公开接受上下文和专用试算上下文分别持有
  accepted/candidate 两份；它不进入 `[q;v;z]`，也不是全局缓存。每个 CVODE 内部接受端点只重算
  四载体投影并推进 candidate，公开推进成功才与时间和物理状态一起提交，失败整体回滚。公开目标
  整体回滚是 ORVD 的强化事务，不冒充 WRL 原样行为。
- 下一核验：G54 已以真实 GZ18 窄局部窗和真实 CVODE 单步执行该合同；G57 已证明跨定义边界的
  原生直线延长不改变 accepted/candidate 所有权。性能测量只作仓外临时观察，不成为正确性门。

### OBS-029 — Maxwell 是具有记忆的悬挂本构，不是更高位车辆对象

- 状态：已确认
- 观察：普通并联弹簧—阻尼满足 `F = F0 - K·(x-x0) - C·dx/dt`，当前 `q/v` 足以唯一确定
  当前力。Maxwell 串联弹簧—黏性本构满足 `x = xs + xd`、`F = K·xs = C·dxd/dt`，消去内部
  变形后得到 `dF/dt = K·dx/dt - (K/C)·F`；同一瞬时位移和速度可因加载历史不同而产生不同力，
  因此每通道必须保存一个力、弹簧伸长或等价内部状态。WRL 选择力 `F` 为连续状态。
- 锚点：WRL `scripts_cpp/drake_sim/src/specialized_suspension.cc` 的普通代数本构，
  `scripts_cpp/drake_sim/src/continuous_maxwell_lateral_damper.cc` 的连续力状态方程，以及 GZ18 P027
  对串联弹簧状态与 C++ 力状态的鉴权。
- 影响：车辆组装层仍只看到悬挂实例；共性力元层按代数弹簧阻尼、串联弹簧阻尼、限幅阻尼、纯
  力偶等真实本构分类。附加状态进入根系统完整连续状态事务，但不伪装成刚体广义坐标。
- 下一核验：为每个 GZ18/IRW 力元列出 `state_size`、状态物理量、单位、初值和导数方程，并决定
  公共名称使用 `SeriesSpringDamper` 还是另一个同义且更自明的领域名称。

  金标禁令。旧设计文档中的历史“金标”措辞不得覆盖现行工程规则。
- 影响：测试仍可验证启动输入的物理自洽和加载失败合同。目标轮载等明确声明为启动约束的字段可在

## 迁移前五组只读清单（规划初期快照）

这些清单保存 05:15 规划阶段的盘点框架和来源入口，不删除其历史考古。其已裁决部分已经吸收进

### 清单 A — 力元与扳手合同

逐个列出接触、悬挂、空气簧、阻尼、抗侧滚、抗蛇行、牵引杆、驱动和重力：

- 本构、PRELOAD、阻尼和支承力矩语义；
- 是否有内部状态、离散更新或事件；
- 应归入共性能力还是车型配置；
- ORVD 当前可表达路径与缺口。

### 清单 B — 附加状态的所有权与生命周期

逐项盘点 Maxwell 状态、接触温启动提示、控制器状态、缓存、离散/抽象状态以及任何求解器旁挂量：

- 试算、接受、拒步和重初始化时如何提交或回滚；
- 哪个版本源使相关缓存失效；
- 多上下文、并行求值和重放时是否隔离。

### 清单 C — 轮轨接触适配合同

明确轮轨接触纯算法与车辆运行时之间的窄边界：

- 运动学输入、轨道/型面身份和接触人格；
- 具名接触点、接触基、力与力矩输出；
- 工作区所有权、线程安全和热路径分配；
- 状态求值、采样保持和接受步更新时相；
- 共性公式、车型参数和科学观察器的依赖方向。

目标是让接触算法保持模型中立的数值能力，而不是复制旧 Drake `LeafSystem`。

### 清单 D — 车型拓扑与 ORVD 能力差矩阵

分别为 GZ18 和 IRW 列出：

- 刚体、质量、质心、惯量参考点和体固标记；
- 关节类型、自由度顺序、执行器和约束；
- 当前 ORVD 可直接表达、需小幅扩展、需新架构决策的项目；
- 源模型质心惯量到 ORVD 体原点单位惯量的显式转换；
- 状态坐标映射与可观察物理不变量。

### 清单 E — 静平衡、PRELOAD 与启动身份

逐项记录：

- 静平衡未知量、残差、缩放和接触成立条件；
- 名义 PRELOAD 与实际力元本构的关系；
- 轨道偏移、轮速和上下文相关启动量的生命周期；
- 平直/曲线、不平顺启停和移动初始化如何共享或重解身份；
- Ceres 只应解决哪些变量，哪些身份必须作为输入冻结。

## 当前禁止直接搬运的结构

以下项目不是永久否决，但在形成新裁决前不得整块移入 ORVD：

- Drake `Diagram`、`LeafSystem`、`Context` 和车型专用系统编排层；
- IRW/GZ18 各自的大型运行器、积分器驱动器、CSV 写出器和静平衡脚本；
- 依赖硬编码 `q/v` 索引或车型名称的共性接口；
- 没有试算/接受/拒步事务的普通可变接触或 Maxwell 状态；
- 车型 JSON、生成头或魔数对模型中立模块的反向依赖；
- 旧名称包装、双路人格开关和历史错误行为兼容层；
- 把历史轨迹、文件哈希或逐位一致当成正确性来源的测试。
