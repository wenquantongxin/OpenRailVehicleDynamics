# ORVD 计算性能文档

本目录管理 ORVD 在**保持既有车辆动力学资格结论**前提下的计算性能工作。它与已经封存的
G01–G82 迁移路书分开：车辆能力是否存在由迁移路书回答，现有能力怎样减少墙钟、CPU 和内存开销
由本目录回答。

## 计时术语

- **动力学推进墙钟**：CVODE、车辆右端和接受态事务的墙钟时间。
- **观测墙钟**：在既有密集状态上重放车辆与轮轨观测的墙钟时间；归档样本不成为额外积分停靠点。
- **运行器分段总计**：推进、观测、端点诊断和工件写出的分段计时之和；不包含随后写性能摘要、
  发布目录以及进程启动／退出的尾部。
- **完整进程墙钟**：从外层包装器启动资格程序到其退出的实测墙钟；这是端到端实时系数的权威分母。
- **实时系数**：模拟时长除以墙钟时间。大于 `1` 表示平均吞吐快于实时，但不证明最坏时延或硬实时。

引用性能数字时必须说明工况、源码提交、Release 配置、线程数、CPU 亲和性和上述计时边界。短窗只
用于筛选与定位，不能线性外推为 `16/20/30 s` 长窗结果。

## 证据与提交纪律

1. 临时轨迹、性能摘要、剖析结果和试验脚本放在仓库 `tmp/` 或仓外临时目录，不进入 Git，也不作为
   产品输入、测试期望或永久金标。
2. 仓内只保存算法、解析误差界、接受／否决结论和可重算的证据入口；不固化某台机器的速度门或
   输出哈希。
3. 逐位等价优化必须保持物理观测、接触斑记录和积分统计完全一致。具有明确误差预算的优化必须
   重新运行 GZ18 与 IRW 的冻结长窗，并继续与 SIMPACK 比较。
4. 候选通过后直接替换唯一实现；候选失败则撤回，不在产品中留下兼容开关、旧算法分支或自由组合
   的性能旋钮。
5. 基线与候选交错或配对复跑两次，结果以算术平均和最小—最大范围报告。两次后仍无法区分收益与运行
   噪声时，候选挂起或否决，不继续追加重复样本；不以单次最快成绩替代稳定结论，也不把平均吞吐写成硬实时能力。

## 当前状态

专项分支已经完成 GZ18 存在性研究，但它在 IRW、100 Hz 控制和跨平台闭包进入主线之前分叉。
因此不合并整分支，也不机械摘取提交。PERF-01 五工况基线与 PERF-02 型面定位减算已收口，
当前进入精确接触缓存链。实施状态、当前 Goal 与完成门只以
[双车型计算性能迁移路书](PERFORMANCE_MIGRATION_ROADMAP.md)为准。
