# libs/multibody_model

**职责**：模型中立的程序化多体建模门面。

G29 提供构建所需的第一方类型与加入期失败语义：刚体、直接附着刚体的固定坐标系、转动/移动/焊接关节，以及显式自由体关系。公共头不出现 Drake 类型、上游索引或 mobilizer；PIMPL 内部独占 landed 刚性树。

`RigidBodyHandle`、`FrameHandle` 与 `JointHandle` 只用于把已经加入同一模型的元素交回模型，不暴露 ordinal，也不能由公共消费者伪造。

公共 fixed frame 与关节端点映射到 landed tree 中同一个真实 frame，不复制 pose 去生成隐藏的 joint frame。自由关系在内部使用 quaternion floating joint 实现，但该实现类型不对外，且不列入公共关节名称、句柄或计数面。

## 已落地(G30)

模型有两段生命：描述期收元素，最终化后不再收元素、回答关于它成了什么样的问题。这条界线不是仪式——描述期给出的计数或坐标区段，回答的是「到目前为止说了什么」，那是另一个问题，而且下一次调用还能改变它的答案。

准确地说：关于最终拓扑的查询——计数、枚举、按名称查询、由句柄取名、是否自由、坐标区段、创建上下文——都要求最终化。三样东西不要求，因为它们不依赖最终化：两个建模辅助（`world_frame()` 与 `body_frame()`）、模型自身状态（`is_finalized()`），以及重力向量——它从模型存在的那一刻就有值，最终化只是让它不再可写。

`Finalize()` 分两段。**预检**只读门面自己的森林、不写底层 tree：每个非 World 刚体必须能到达 World，不可达者一次点名列全。因此预检失败**不是**终止态——模型描述的仍然是它原本描述的东西，补上缺的关系可以再次最终化。（可达性判定会压缩它走过的路径，所以那份记账不是逐字节不变的；它的含义不变。）**提交段**（注入私有关节、进入底层 `Finalize()`）开始前先记下「已了结」，走完才清除，所以该段任何抛出都让模型进入响亮的终止态：底层 tree 处于无人能描述的状态，没有可回退的东西，重试只会建在上面。异常不被捕获也不被复述。

可达性是预检唯一要查的事。G29 的加入门以并查集连通性拒绝成环，每条获准关系恰好合并两个分量，所以建模结束时图必然是森林——「至多一条路径」在 G29 就已经关闭，G30 只补「至少一条」。

私有 quaternion 关节在**最终化时**注入，不在 `DeclareFreeBody` 当场建。声明当场仍然执行句柄解析、重复声明与「是否已连通到 World」三项检查，所以没有任何失败被推迟。延迟买到的是名称空间：若关节当场就进了 tree，调用方随后用 `__orvd_free_body_<n>` 命名一个完全正常的公共关节会被拒绝——而这个名字被占用一事，从来没有任何接口告诉过他们。

最终化成功后结构、重力向量与模型自有力元常量冻结，全部 `Add*`、`DeclareFreeBody`、`SetGravityVector` 与第二次 `Finalize()` 都在入口拒绝，并说出被拒的是哪一件事。底层 tree 也会拒绝最终化后的改动，但那是另一层在抱怨另一个名字下的元素；本层的闸门必须自己成立。

查询范围按语义划分而不按底层存储：刚体查询不含 World（没有质量属性、不受力、不加速，调用方每次都要跳过它）；frame 查询含 World 帧、每个刚体自己的帧和门面创建的固定帧；joint 查询只含调用方加过的关节，实现自由关系的那个不在其中。句柄在模型生命周期内稳定，支持按名称查询与确定顺序枚举，不为不存在的删除/重建语义引入代际句柄。

`GeneralizedPositionRange` 与 `GeneralizedVelocityRange` 是两个独立类型，互不可转换、无默认构造、不能由调用方构造。它们不是同一个数：自由体有七个位置、六个速度，因为四元数要用四个数承载三个自由度。焊接关节报出一个起点、长度为零——那是它的坐标本该开始的地方，可以合法地取空块，也不属于任何人。自由体的位置区段内部：前四项是四元数，按 w、x、y、z 排列，后三项是刚体原点在世界系中的位置；速度区段内部：前三项是角速度，后三项是平移速度。不写明这一点，区段就只能取块、不能读。每个广义坐标恰好属于一个公共关节或一个显式自由体：**属于不了任何人的坐标，就是底层给未声明关系补上的自由度**，而这正是门面存在的理由。

`MultibodyEvaluationContext` 只能由已最终化的模型签发，不可复制不可移动，模型必须比它活得久。它只公开 q 与 v 的只读视图；写入需要模型知识（哪几个数是四元数、什么样的四元数是合法的），所以经模型完成而不在 context 上另开可变入口。

## 已落地(G31)

`RigidPose` 只陈述一个数学值：一个旋转和一个平移。它关联的是哪两个坐标系，是查询的事，写在查询的名字里——`CalcPoseInWorld(context, body)` 给出的就是该刚体的坐标系在世界系中的位姿。把坐标系写进类型会让 `WorldPose` 成为一个相对位姿查询无法返回的类型，而第一个这样的查询要么另造一个类型、要么说谎。

取值器带引用限定符。查询按值返回位姿，所以 `const auto& R = model.CalcPoseInWorld(...).rotation();` 若取值器返回成员引用，就会绑定到一个语句结束即消失的对象；`&&` 与 `const&&` 两种右值重载都按值返回，让该引用绑定到独立结果并延长其生命周期，`const&` 重载则为调用方自己持有的位姿保留零拷贝读取。

q 与 v 的写入经模型而不经 context：哪几个数是四元数、什么样的四元数可用，是模型知识。四元数按写入的样子原样存放——归一化写回会回答另一个问题，而调用方永远不会知道读回来的不是自己写的。

位姿查询与状态写入都先核对 context 确实由本模型签发，并点名拒绝外来 context。context 的私有实现只保存签发模型的身份值，不保存能反向导航回模型或树的指针。

G46 将该门面安装并导出为 `ORVD::multibody_model`；安装头不暴露 vendored Drake 或接入层类型。

## 已落地(G32)

`FrameSpatialVelocity` 公开两个具名三维量：角速度和运动坐标系原点的平移速度。单位分别写在取值器名称中；公共接口不暴露需要调用方记忆上下三项顺序的匿名六维向量。与 `RigidPose` 相同，右值取值器按值返回，避免从查询返回的临时对象中留下悬空引用。

三个查询分别回答：刚体 frame 相对世界并以世界表达、任意 frame 相对世界并以世界表达，以及运动 frame 相对指定参考 frame 并以第三个 frame 表达。空间速度属于 frame；只有平移分量在运动 frame 的原点取值，不是位于两个不同点的世界平移速度之差。测量体、参考体和表达坐标系在函数名与参数名中写明。

解析测试覆盖非共面串联与分支、带偏置的固定 frame、自由体、以 World 为 child 的反向转动/移动关系、零速度和速度线性。候选端与 Drake 参考端在两个独立进程中比较所有刚体 frame 的空间速度（平移分量取刚体原点）、一个三坐标系相对空间速度以及速度状态回读；场景同时含反向遍历分支、旋转且平移的安装座和自由体。

缓存重算计数由内部绑定测试观察，不进入公共门面：冷查询计算位置、跨节点 Jacobian 与速度槽各一次；热查询不重算；改 `v` 只重算速度槽，改 `q` 或固定坐标系位姿按需重算三者，刚体惯量和执行器参数不触发速度重算。三种真实失效后的速度缓存全部字段均与同状态冷上下文对照。

## 已落地(G33)

广义速度到位置导数的映射与逆映射均接收显式向量，不偷读上下文中的速度。自由体四元数区段按 wxyz 解释；正映射使用写入时的安全非单位四元数且不归一化写回，逆映射丢弃位置导数中沿四元数径向的分量。`v -> qdot -> v` 是恒等映射，任意 `qdot -> v -> qdot` 是切空间投影。

空间加速度接口接收显式 `vdot`，一次返回所有公共刚体 frame 相对世界并以世界表达的角加速度与刚体原点平移加速度。`vdot` 是调用期输入，不进入长期缓存。首个 Jacobian 接口刻意收窄为近期消费者需要的算子：关于广义速度、世界测量、世界表达、作用在具名刚体固定点；不恢复字符串或枚举式万能选择器，也不恢复 `BlockSystemJacobianCache`。

解析验收逐列用公共位姿的中心差分核 Jacobian，并独立验证 `A(q,v,vdot) = A(q,v,0) + J(q)vdot`。跨进程比较用与状态速度不同、分量两两不同的稠密探针比较映射与 `J·probe`，另用不是由正映射生成且带四元数径向分量的 qdot 核逆映射。整个 Jacobian 的列序与符号由本地逐列有限差分承担，跨进程不把一次探针响应夸大成完整算子等价。

固定坐标系位姿是上下文参数的唯一权威来源。速度和加速度的点移与位姿、Jacobian 一样读取同一上下文值；不再沿用 Drake v1.54 在这两处读取构造期默认位姿的行为。

## 已落地(G34)

`CalcGeneralizedMassMatrix(context, output)` 接收调用方已经定为 `nv×nv` 的矩阵引用，直接在该存储中运行 landed 复合刚体算法。必需输出没有空值语义，入口不接受指针、不自动调整尺寸，也不建立逐列逆动力学适配层。模型未最终化、上下文来自别的模型或矩阵尺寸错误时，输出保持不变并明确失败。

质量矩阵只依赖构型、固定坐标系位姿、刚体惯量和执行器反射惯量。只改广义速度既不改变结果，也不使质量矩阵所需的 q-only 缓存重算；内部验收同时比较同状态冷上下文的完整值和各槽提交次数，避免“漏声明依赖但热槽仍被沿用”的假通过。

完整算子有三条彼此独立的证据：复合刚体算法逐列对照调用方预分配的逆动力学；公共测试从逐体动能经极化恢复所有矩阵元素；跨进程候选与 Drake 参考逐列比较。夹具刻意让公共刚体加入顺序不同于森林 Mobod 顺序，并含偏心质心、非零惯量积、旋转平移安装座、非平行转动/移动自由度、焊接后代和显式自由体。

## 已落地(G35)

逆动力学、速度偏置、重力施加力和关节阻尼施加力均为具名接口，直接写入调用方预先定好尺寸的向量。符号统一为 `required = M·vdot + bias - gravity - damping`；正的 applied 项表示实际施加到系统的力。转动与移动关节阻尼是带单位的必填建模参数，没有旧的默认零阻尼重载。

内部求值上下文私有复用力缓冲、空间加速度、反作用力和零广义加速度。有效调用不形成质量矩阵、不复制整块结果；单转动解析夹具把惯性、重力、阻尼和组合项分别观测。

## 已落地(G36)

调用期外力使用三种具名记录：关于刚体固定点 Q 取矩并在坐标系 E 表达的 body wrench、转动关节力矩和移动关节力。必需输出为引用，不提供空指针语义；焊接关节没有 effort 兼容入口。

具名坐标系原点可由最终化模型和当前上下文解析为一个不可拆分的“承载刚体 + 体固点”值；焊接后的
子体仍保留自身作为载荷承载体。车辆力元据此只保存坐标系身份，不从外部车型记录重建第二份落点。

最终化模型创建不可复制移动、与模型绑定的前向动力学工作区。每次调用先覆盖模型力缓冲，再叠加调用期外力，直接运行 landed O(n) ABA 第二、第三趟；工作区另预分配 qdot 暂存以输出 `[N(q)v; vdot]`，不保存上下文、输入、版本或上次结果。局部测试覆盖偏置点力矩移位、单移动 `F=ma`、ABA/RNEA 往返和 A→B→A 复用。
