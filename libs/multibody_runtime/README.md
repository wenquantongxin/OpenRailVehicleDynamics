# libs/multibody_runtime

**职责**：多体状态、缓存与刚性树求值运行时。

- 单一权威运行时上下文：状态只有一个所有者，其余一律为零复制视图（[ADR-0002](../../docs/adr/0002-single-authoritative-context.md)）
- 广义位置、广义速度与有长期缓存消费者的实际参数版本戳，以及上下文之间的隔离
- 固定类型的缓存存储、静态先决条件与惰性求值
- vendored 刚性树与第一方运行时契约的内部绑定

**对应 Goal**：G20–G28。

运行时契约与实际缓存依赖由 G20 从 G16 后的 landed 源码和固定 Drake 来源中的
`MultibodyTreeSystem` 职责现场裁决。缓存条目、值类型与先决条件都不在此处预先写死。
最终化模型不可变并可被多个求值上下文共享；每个上下文独占 q、v、类型化参数、版本和
缓存工作区。运行时基础层只提供状态、版本和不依赖具体值类型的类型化缓存槽；刚性树接入层
组成具体缓存工作区并接收上下文求值，基础层不反向依赖 vendored tree 或缓存类型。
时间、事件、输入端口与离散状态在出现实际多体消费者前不进入本模块。
模型中立的公共建模门面属于 G29–G30，不在运行时尚未成形时提前占接口。

`include/orvd/multibody_runtime/` 是仓内目标的公共编译接口头，`src/` 为实现；当前目标
不安装、不导出，终端公共 API 由 G29 与 G46 收口。公共类型必须用具体职责命名，不以裸
`Context`、`Cache` 或上游内部术语占据接口。

## 已落地(G21、G22)

`orvd_multibody_runtime` 静态库,只链 Eigen 与标准库,零 `drake/` include、零 `drake::`。

- `MultibodyStateLayoutDescription` / `MultibodyStateLayout`：最终化模型的规模。基础层
  不读最终化模型本身——那是 vendored 刚性树,读它会把依赖方向反过来——而是由接入层填写
  描述,布局是校验它之后剩下的东西。状态按 layout 的**对象身份**绑定,不按内容相等:
  两个数值相同的 layout 仍描述不同的模型。layout 必须以地址稳定的左值存在并比状态活得久;
  临时 layout、状态的隐式复制、移动和跨 layout 赋值都不构成合法接口。
- `MultibodyStateInstance`：广义位置、广义速度与上下文可变类型化物理参数的**唯一所有者**。
  读出 const 视图;写入取整值、全部校验通过后才落盘,因此被拒绝的写入让活状态一字不动,
  也不存在「先改活数据、随后提交」的编辑器——那个窗口里的状态既不是旧值也不是新值。
- 参数记录按物理职责命名(`RigidBodyInertiaParameters`、`FixedFramePoseParameters`、
  `JointActuatorParameters`、`RevoluteSpringParameters`、
  `LinearBushingRollPitchYawParameters`),不照搬上游把空间惯量打包成十个匿名数的传输格式。
  变长的关节阻尼直接存于按 layout 切分的平坦向量,不为它再造一个无人消费的拥有型记录。
- 校验只做这一层能判定的:维数、有限性、阻尼/刚度/转子惯量非负、固定坐标系旋转确为旋转
  (校验而不修补)、空间惯量平移到质心后的主惯量非负且满足三角不等式,并且**不误拒合法
  的零惯量**。哪些位置分量是四元数属于模型知识,本层不猜也不静默归一化；零初始化只建立
  存储,能看见 mobilizer 分段的接入层必须在首次求值前写入模型默认位置并拒绝零四元数。

- `MultibodyStateVersion`:一个来源已接受的写事务计数,不是它当前值的哈希。写入同样的
  数值仍然推进——若按值相等跳过,写入路径就得为此把整个向量再扫一遍,而「变没变」也从
  「有没有存进去」变成了「数值等不等」。多推进的代价是多算一次:答案对、功白做,且白做
  被重算计数看得见;少推进的代价是陈旧答案:错,而且无人报告。这个不对称决定了取舍。
  该类型只比相等、只产生后继,不隐式转成整数、不做算术、不排序——缓存问的永远是「和我
  记下的是不是同一个」,而不是「是不是更新」(跨来源比较即无意义)或「差几版」(不表示任何
  东西)。
- 版本源恰好五个:广义位置、广义速度、全部固定坐标系位姿、全部刚体惯量、全部执行器转子
  惯量与传动比。它们正是[运行时契约](../../docs/design/MULTIBODY_RUNTIME_CONTRACT.md)
  证明有长期缓存读取的来源,且三类参数的消费者集合两两不同,因此不能合并。关节阻尼、
  转动弹簧与线性衬套**不获得版本**:没有缓存留存它们的结果,力计算每次现读。无消费者的
  版本不是白给的对称性,而是一个日后会被拿去比较、比较却不意味任何事的数。
- 参数按**类别整体**版本化而非按元素:它们喂养的缓存都是整模型缓存,没有任何消费者能只
  对一个 body、frame 或 actuator 失效,按元素分版本只会划出无人能据以行动的区分。
- 每次带版本的写入固定四步:校验整个输入 → 计算后继版本(计数耗尽则明确失败)→ 写入数据
  → 提交版本。第二步在写入之前,是为了让计数耗尽不会留下「数据已写、版本未推进」——那
  正是陈旧缓存读起来像新鲜的唯一状态;第四步在写入之后,保证单线程求值不会在旧数据仍在
  原处时看见新版本。这不是并发同步机制；首版缓存求值按 G25 保持单线程。版本不静默回绕。

不含时间、离散状态或事件字段:落位树对它们零命中,而为不存在的消费者预留字段,迟早会有人
为错误的理由把它填上。
