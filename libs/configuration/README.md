# configuration

本模块把人工编写的严格 JSON 配置一次性转换为 ORVD 的类型化产品对象。公共接口只接收调用者
明确给出的文件路径；不搜索资源、不读取环境变量、不提供继承、覆盖或默认值填充。

`nlohmann/json` 仅用于本静态库的实现。公共头和安装导出接口不暴露其类型，配置文件在加载完成后
也不再参与轨道几何求值。

线路几何记录由加载器直接形成不可变的 `TrackGeometry`。三个独立剖面分别描述曲率、超高和
中心线上坡坡度；常值段与 Hermite 三次混合段使用不同的精确字段集合。

车型记录加载为可修改的 `VehicleDefinition` 值。科研用户可在 C++ 中直接构造，或加载 JSON 后
显式修改，再交给装配器生成独立的最终化多体模型；装配器不保留对记录的引用。三类记录的字段名
均携带物理含义与单位；JSON 中未知字段会被拒绝，当前已声明字段由显式消费者和聚焦测试覆盖。

已解析启动状态是第三类记录。本模块**加载**它，不求解它：没有静平衡搜索、没有预载求解、没有迭代，
其中任何一个数都不会由其他数重算。记录不携带绝对里程——车辆布局参考体的站位是装配时的实参，
逐体实际站位为「参考站位 + 车型记录的机械站位偏移 + 记录中的已解析站位位移」；逐轴站位是装配的
产物而不是输入。状态写在各体自身站位处的局部轨道系里，惯性系的量在装配时形成，不在记录里存第二份。

`AssembledVehicleSystem` 把模型、力元计划、系统实例与编译计划按构造顺序拥有、反序析构，并从同一次
车型记录快照中自持全部名称族——模型与力元计划只按名字作答、不枚举名字，启动状态的 all-and-only
比对没有别处可读。`AssembleResolvedInitialContext` 先校验后写入：任何一步失败，那个尚未交给调用方的
上下文随异常一起销毁，因此没有半写状态。它必须在构造 `SystemContinuousStateAdvancer` **之前**调用。
