# configuration

本模块把人工编写的严格 JSON 配置一次性转换为 ORVD 的类型化产品对象。公共接口只接收调用者
明确给出的文件路径；不搜索资源、不读取环境变量、不提供继承、覆盖或默认值填充。

`nlohmann/json` 仅用于本静态库的实现。公共头和安装导出接口不暴露其类型，配置文件在加载完成后
也不再参与轨道几何求值。

线路几何记录由加载器直接形成不可变的 `TrackGeometry`。三个独立剖面分别描述曲率、超高和
中心线上坡坡度；常值段与 Hermite 三次混合段使用不同的精确字段集合。

车型记录加载为可修改的 `VehicleDefinition` 值。科研用户可在 C++ 中直接构造，或加载 JSON 后
显式修改，再交给装配器生成独立的最终化多体模型；装配器不保留对记录的引用。记录可直接声明
自由体、固定框、转动副、Ball-RPY、焊接关系和各个类型化力元。固定框旋转使用紧凑的同向形式或
明确的 `body <- frame` 三行旋转矩阵，不经欧拉角中转。所有字段名均携带物理含义与单位；JSON
未知字段会被拒绝，当前已声明字段由显式消费者和聚焦测试覆盖，不存在数字格式编号、旧格式试读
或兼容别名。

随包 IRW 记录是第二个真实消费者。它把四个轴桥声明为轮轨接触载体，同时保留八个车轮体和八个
独立转动副；载体身份不负责推断车轮自旋。8 个 Ball-RPY、8 个半角共同中点衬套、36 个平动力元、
2 个侧滚元和 2 个 Maxwell 通道由共同装配入口编译为 `nq=81`、`nv=74`、`z=2` 的被动系统。
H3 启动、IRW 型面与接触人格不属于该机械记录，也尚未由当前 IRW 资产提供。

已解析启动状态是第三类记录。本模块**加载**它，不求解它：没有静平衡搜索、没有预载求解、没有迭代。
GZ18 只有一条显式展开关系：共同启动速度 `V0` 写入七个自由体的纵向速度，并与启动等效滚动半径
共同生成四个轮对自旋和八个轴箱转臂关节速率；横垂速度与附加角速度仍逐体保存。该半径的取值用于复现本记录已资格化的移动启动轮速，而不是本仓现场求解的接触半径或标称轮径。它适用于本记录的轮轨型面、接触策略、载荷工况与轨型偏移组合；改变这些条件时，配置作者须同步更新它。
记录不携带绝对里程——车辆布局参考体的站位是装配时的实参，
逐体实际站位为「参考站位 + 车型记录的机械站位偏移 + 记录中的已解析站位位移」；逐轴站位是装配的
产物而不是输入。状态写在各体自身站位处的局部轨道系里，惯性系的量在装配时形成，不在记录里存第二份。

`AssembledVehicleSystem` 把模型、力元计划、系统实例与编译计划按构造顺序拥有、反序析构，并从同一次
车型记录快照中自持全部名称族；转动副和 Ball-RPY 名称分别承载，避免把 `1q/1v` 与 `3q/3v`
展平为同一类，并为各车型的类型化启动映射保留唯一 all-and-only 名单。模型与力元计划只按名字
作答、不枚举名字。
`AssembleResolvedInitialContext` 先校验后写入：任何一步失败，那个尚未交给调用方的
上下文随异常一起销毁，因此没有半写状态。它必须在构造 `SystemContinuousStateAdvancer` **之前**调用。

随库 GZ18 示例只在直线、水平、零超高且无轨道不平顺的启动段上获得资格。科研用户可以把同一记录放到
坡道、曲线或超高段，装配器会按完整坐标变换执行且不会禁止；这种外推不承诺复现参考软件的 7 型铁路
关节输运动力学。车辆也可处在基础线路 JSON 定义区间以外；此时统一消费 `TrackGeometry` 的原生
边界切线延长，而不是把站位夹回端点或给资产补空白段。零速与反向启动会被拒绝；近零速和随后跨
零速的轮轨物理尚未资格化，正数输入获准装配不等于这类工况已经得到验证。
