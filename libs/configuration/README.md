# configuration

本模块从显式路径加载 JSON，形成线路、车辆、轮轨配置、控制参数与起动状态的类型化对象。
加载器校验必需字段、物理单位与取值范围，拒绝未知字段。
`nlohmann/json` 保持在实现内部，公共接口使用 C++ 类型。

## 资产与装配

线路记录形成不可变的 `TrackGeometry`。曲率、超高与纵坡分别由常值段和过渡段描述。

轨道不平顺可使用已存储空间场，或由完整 PSD 规格和显式随机种子生成。
`ResolveTrackIrregularityField` 返回统一的空间场；生成路径同时给出频带、布置及通道种子元数据。

车辆记录形成 `VehicleDefinition` 值，描述刚体、固定架、关节和类型化力元。调用方可显式修改该值，
再装配独立的多体模型。固定架旋转以同向形式或 `body <- frame` 矩阵给出。

`AssembledVehicleSystem` 持有模型、力元计划、系统实例与编译计划，并保留启动装配需要的名称绑定。
定轴串联元件与点对点串联元件分别按名称解析，内部力统一以 N 为单位。

## 起动状态

`AssembleResolvedInitialContext` 将具名初始量换算并写入完整 `[q;v;z]`，在建立系统推进器前调用。
装配先校验模型绑定、重力、名称覆盖及量纲，再形成上下文。

自由体位姿写在各体站位处的局部轨道系中；实际站位由运行参考站位、机械布局偏移及记录中的偏移相加得到。
回转副保存角度与速率，Ball-RPY 保存角坐标及父系表达的物理相对角速度。

起动记录可显式给出轮转速，也可声明由共同速度和有效滚动半径生成的公共自转关系。
两类串联元件各有具名初始力，按已解析索引覆盖 `z`；平动力元名义力和钢轨型面基准偏移写入配套参数。
目标轮载随装配结果保留，供初态核对使用。

## 控制参数

车轮转矩调理记录给出速度节点、牵引和再生限值、变化率及方向参数，形成不可变的调理器。
控制记忆和事件时钟由调用方持有。

公共头位于 `include/orvd/configuration/`，实现位于 `src/`。
