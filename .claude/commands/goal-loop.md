# /goal-loop — Goal 循环推进规程

按路书逐 Goal 推进本仓库:每轮以 Codex 裁决开工、以 Codex 复核收尾,无阻塞则自动进入
下一 Goal。本文件既是规程文档,也是可执行提示词:收到 `/goal-loop` 即从「第 0 步」开始
执行路书当前 Goal 的一轮;循环由 Claude 驱动,Codex 是裁决与复核方,用户随时可中断。

## 固定量

```
路书        docs/planning/rail_vehicle_dynamics_migration/MIGRATION_ROADMAP.md
            (唯一进度权威,「当前 Goal」条目;G47 起)
Codex 线程  019fc40e-d0c6-75b3-b34d-4640982031ec(代码移植与重构)
Codex 模型  gpt-5.6-sol,model_reasoning_effort=ultra(单次分析普遍 10–20 分钟)
交接目录    ~/.codex/handoff/(仅供当前裁决或复核请求临时传输)
交接文件    每步两件:GXX_<step>.stage.txt / GXX_<step>.out.log；结论读完立即删除
```

`docs/planning/drake_multibody_runtime_decoupling/DRAKE_MULTIBODY_RUNTIME_DECOUPLING_ROADMAP.md`(G01–G46)已封存,不再有
「当前 Goal」;任何时刻只有一个路书文件带该条目。旧 Codex 线程同样封存,不再向其发送载荷。

## 不变量(任一被破坏即阻塞)

- 只提交 `main`,永不 push,不建分支与 PR。
- wheel-rail-lab、Drake 源码克隆、`/opt/drake` 只读;仓外探针不落入任何仓库。
- 仓库内不写机器路径;Drake 位置只经 `CMAKE_PREFIX_PATH` 等标准 CMake 参数传入。
- Codex 汇报的一切承重数字(通过数、退出码、计数)在采信前第一手复跑;
  呈报用户时「其声称 / 我复跑」两列并排。复跑的对象是**该论断为假的最短路径**,
  不是它顺带提到的任何事实——机制性论断尤其要先写出「若它为假,哪一个事实会不同」,
  再去验那一个。
- **载荷中一律自称 Claude,不用「我」。** 发给 Codex 的每一份 stage 文件都会进入它的
  上下文;第一人称会让它把 Claude 的判断误当成自己的推论,溯源随之失效。同理,引用
  Codex 上一轮结论时写明「Codex 上轮称」,不与 Claude 的复跑结果混写。
- **中文按正常书写习惯排版,不按列宽硬折行。** 提交信息与 stage 载荷里的中文段落写满一行,
  只在语义分段处换行;英文段落、代码、路径、命令和表格仍按原有对齐方式。硬折行会把词与句子
  从中间切断,读的人要在断口处重新拼接。
- **不在他方写入期间读取并据此下结论。** Codex 线程以 danger-full-access 运行,会边分析
  边改文件。发送后到收到结论之间,工作区处于中间态:此时读到的缺失、缩水或半成品都不是
  事实。要下结论必须先确认没有 codex 进程在跑(`ps -eo pid,etime,cmd | grep '[c]odex exec'`),
  否则只能报告「正在运行,状态未定」。
- **不得在载荷中要求对方删除文件或成段删除文档内容。** 复核方的最小修复权用于修正,不用于
  清理;删除只能由该文档的作者或项目负责人裁决。若 Claude 认为某处该删,写明理由并请求裁决,
  不写成指令。
- 用户工程铁律优先于 Codex 裁决,冲突即执行铁律,并在下一轮载荷中说明。清单见下节。
- 向 Codex 发送前工作区必须干净:该线程以 `approval_policy=never` + danger-full-access
  运行,会直接改码并提交。
- **历史线性,署名归属作者。** 谁写的改动谁提交、谁署名:Claude 的实施提交只登记
  `Co-Authored-By: Claude Opus 5`;Codex 的扫尾修复**另建后续提交**,只登记它自己。
  **禁止 amend 他人已形成的提交**,也不重写已形成的历史。理由是溯源:被 amend 的提交
  再也看不出哪些改动来自复核,而复核发现的缺陷恰恰是最值得日后回看的部分。
  两者的提交信息都用中英双语。
- 不假定 scratchpad、`/tmp` 或交接日志会自动销毁。当前请求吸收结论后立即删除对应临时
  文件；不得把它们当冷存档或历史证据。

## 工程铁律

### 变更纪律

- 需求或接口语义不明确时,停止并提问 Codex,不以猜测填补。
- 语义命名:禁版本号与 `classic`/`new` 式区分;第一方算法按真实物理功能命名,不用厂商
  对齐、调试或开发期措辞。

### 失败策略:显式失败优于静默兜底

- 在入口处校验前置条件,违反即抛出,并携带定位所需上下文(实际输入、来源、期望)。
- 禁止:吞掉异常、以默认值掩盖缺失输入、`hasattr`/try-import 式能力探测、同一能力的多条
  回退路径。
- 本条禁止的是「静默修复」,不是「前置断言」。断言与契约检查应当增加,不应删减。
- 不为调用方的错误加产品侧兜底,不添加过度设计的回退或防御性包装。
- 用户配置属不可信输入,逐字段严格校验;产品内部已由类型和前置断言约束的输入不重复解析。
  两者是不同信任域,不得互相援引来放松其中一侧。

### 测试

- 断言指向不变量与性质(守恒、单调、边界、异常路径),不指向某次运行的具体输出。
- 禁止把运行结果固化为期望值(golden/snapshot)充当回归依据;数值比较须给出容差及其物理
  或数值依据。跨实现条件良好非零连续量的默认相对误差为 `1e-8`,近零量按物理量纲声明绝对限。
- 测试随契约演进:契约变更即重写对应测试,不为旧行为打补丁。
- 仅当被测能力被真正移除时方可删除测试。禁止为使测试通过而删改测试或放宽断言——测试失败
  时先定位实现。依赖锁文件与二进制资产的完整性哈希不在此禁令之列。
- 判别力优先于数量:每个 Goal 至少一次「故意破坏 → 必须失败 → 还原 → 必须通过」自证。
  不建脆弱的超大测试,不把长时间重跑的动力学仿真当作日常回归门。

### 兼容性与技术债

- 不保留向后兼容层、废弃别名、版本分支;接口变更即同步更新全部调用点。
- 同一能力只允许一条实现路径,发现重复实现即合并。
- 不留 TODO/FIXME 及注释掉的代码;当期问题当期解决,无法解决则显式失败并报告,不得挂起。
- 不主动引入已知技术债;不以牺牲正确性与可维护性为代价做猜测性优化。
- 新代码不得遗留死代码、占位实现、无主的待办。

### 证据

- 不把机器路径、环境状态、固定输出快照、特定提交或固定哈希当作功能正确性的主要证据;
  优先验证行为、接口契约、不变量和实际结果。
- **本条禁止的是「新增冻结物」,不是「记录出处」。** 规划、裁决与观察文档里的上游提交号、
  外部工件路径、上游文档编号回答的是「这个决定当初依据什么」,属溯源,应当保留并随讨论增补。
  禁止的是让它们成为产品运行身份、完成门或数值金标。两者的判据是用途,不是字面出现与否——
  不得因为文档里出现哈希就去清理它。
- 探索性脚本与临时探针在任务完成后删除,不归档、不留压缩包或软链接。

## 一轮六步(G := 路书当前 Goal)

0. **前置**:`git status --porcelain` 为空;路书当前 Goal 与本轮一致;上一轮的全部线性
   提交都已审读消化。
1. **侦查**:通读 G 的产物/完成门/明确不做;通读将触及的文件与相邻代码;必要时做只读
   探针。产出四件:已核实事实、困惑点与我的倾向、实施草案、完成门清单。
2. **裁决请求**:按模板 A 写 `GXX_ruling.stage.txt`,后台发送,等完成,取最后一个
   codex 块；结论进入实施决定后删除本步 stage/out。模板 A 明令 Codex 本轮不改码。
3. **实施**:按裁决(与铁律)落码;判别力自证至少一次(故意破坏 → 必须失败 → 还原 →
   必须通过);全部完成门跑通;更新路书勾选与当前 Goal;提交 `main`。
4. **复核请求**:按模板 B 写 `GXX_review.stage.txt`,后台发送,等完成,取结论；完成第 5 步
   的第一手复跑后删除本步 stage/out。模板 B 允许 Codex 自行最小修复,但其修复必须落在
   **它自己的后续提交**里,不得 amend 第 3 步的提交。
5. **收尾判定**:复跑其声称的全部门与负控并两列对照;审读其每一处改动(命名违例、
   防御性堆积、兼容层 = 立即小规模重构);向用户简报;无阻塞 → G+1,回到第 0 步。

## 发送与等待(会话机制)

写载荷一律落文件,不走命令行参数:用 Write 工具直写,或 shell 内
`cat > 文件 <<'PAYLOAD'`(PAYLOAD 的引号必须有——关闭一切变量与反引号展开)。

发送命令经 Bash 的 `run_in_background` 执行,**不要**写尾部 `&`:harness 跟踪该进程,
退出时自动唤醒会话;写了 `&` 则命令立即返回,唤醒信号丢失,只能盲等。

```bash
repository_root="$(git rev-parse --show-toplevel)"
cd "$repository_root" && codex exec resume 019fc40e-d0c6-75b3-b34d-4640982031ec -m gpt-5.6-sol -c model_reasoning_effort=ultra - < ~/.codex/handoff/GXX_ruling.stage.txt > ~/.codex/handoff/GXX_ruling.out.log 2>&1
```

- UUID 必须写全:短前缀会被当线程名解析而失败,且 UUIDv7 带时间前缀,同秒会话会撞前缀。
- `-m` / `-c` 对既有线程是冗余保险,保留不删。
- 超过约 40 分钟未被唤醒才做活性检查,任一在涨即活:
  `ps -eo pid,etime,cmd | grep '[c]odex exec'`;`wc -c` 该轮 out.log。
- 取结论:`grep -n '^codex$' <out.log>` 定位,读最后一块。`exec` 独占行是命令回显,
  不是结论。VS Code 侧 app-server 不自动刷新,也不妨碍 resume,两边互不干扰。
- 交接文件只是传输介质。不得因为“以后也许复查”保留整份日志；需要长期成立的决定写入
  路书、ADR 或代码测试，随后删除 stage/out。

## 外置工作区

大型构建树、编译缓存、只读源码克隆与仍在使用的一次性探针放在外置卷,按功能命名。位置
经本机 `CMakeUserPresets.json`(不入 Git)或构建参数提供,**机器绝对路径不进入任何受
跟踪文件**。不建兼容性软链接,不预造用不到的目录,一次性探针裁决吸收后即删。

## 阻塞条件(停循环,报告用户,等待指示)

需要 sudo、断网、磁盘或关键库缺失;codex 线程无法 resume;我的复跑与其声称不符且无法
归因;其提出架构级变更(超出路书与已接受 ADR);用户铁律与裁决冲突且属未定事项;
同一 Goal 两轮复核仍不收敛。

## 批次

默认一轮一个 Goal。当前路书(G47–G55)没有预先裁定的合批;新的合批须在上一轮模板 A 中提案并
获裁决,不得现场合并。
